    1. أطراف المحادثة: العميل والخادم

    1. The Talkers: Client and Server

    العميل Client: برنامج يبدأ الاتصال بإرسال طلب إلى برنامج آخر ينتظر الطلبات، مثل المتصفح وتطبيق الهاتف، ويُطلق الاسم أحيانًا على الجهاز نفسه.

    Client: a program that starts the communication by sending a request to another program that waits for requests, such as a browser or a phone app; the name is sometimes used for the device itself.

    الخادم Server: برنامج يعمل باستمرار، ينتظر طلبات العملاء، ويعالجها، ويرد عليها. ويُطلق الاسم أيضًا على الحاسوب الذي يشغّله.

    Server: a program that runs all the time, waits for clients' requests, processes them, and replies. The name also refers to the computer that runs it.

  8. الصفحة 8 من 40

    نص الصفحة 8

    للتذكر: العميل هو اللي بيبدأ الكلام، والخادم عمره ما بيبدأ؛ دايمًا بيستنى ويرد.

    To remember: the client starts the talk; the server never starts, it always waits and replies.

    معلومة تميزك

    EXTRA INSIGHT

    «العميل» اسم دور، لا نوع جهاز. فالجهاز نفسه قد يكون عميلًا في موقف، وخادمًا في موقف آخر.

    “Client” is a role, not a type of device. The same device can be a client in one case and a server in another.

    Client here

    خادم هنا

    The client is the program (the browser or app), not the person using it.

    شخصيات أخرى في القصة

    Other characters in the story

    المتصفح Browser: برنامج عميل يطلب صفحات الويب ويعرضها لك.

    Browser: a client program that requests web pages and displays them for you.

    خادم الويب Web server: يستقبل طلبات HTTP ويرسل الصفحات والملفات.

    Web server: receives HTTP requests and sends pages and files.

    خادم التطبيقات App server: يشغّل منطق التطبيق، مثل التحقق من كلمة المرور.

    App server: runs the application's logic, such as checking a password.

    الواجهة الخلفية Backend: الجزء الذي يعمل على الخادم ويعالج الطلبات.

    2. الرسائل: الطلب والاستجابة

    2. The Messages: Request and Response

    الطلب Request: رسالة من العميل إلى الخادم

    Request: a message from the client to the server

    طريقة الطلب: ماذا يريد العميل، مثل GET.

    The method: what the client wants, such as GET.

    عنوان المورد المطلوب URL.

    The URL of the requested resource.

    الرؤوس Headers: معلومات إضافية عن الطلب.

    Headers: extra information about the request.

    الجسم Body أحيانًا: البيانات المرسلة، مثل بيانات نموذج.

    Sometimes a body: the data being sent, such as form data.

    الاستجابة Response: رسالة من الخادم ردًا على الطلب

    Response: the server's message replying to a request

    رمز الحالة: نتيجة الطلب، مثل 200.

    The status code: the result, such as 200.

    الرؤوس: معلومات إضافية عن الاستجابة.

    Headers: extra information about the response.

    الجسم غالبًا: المحتوى المطلوب، مثل صفحة HTML أو صورة أو بيانات JSON.

    Usually a body: the requested content, such as an HTML page, an image, or JSON data.

    القاعدة الذهبية

    Golden Rule

    لكل طلب استجابة واحدة تقابله.

    Every request gets one matching response.

    3. لغة المحادثة: HTTP

    3. The Language: HTTP

    البروتوكول Protocol: مجموعة قواعد متفق عليها تحدد شكل الرسائل وترتيبها، وكيف يفهمها كل طرف.

    Protocol: a set of agreed rules that sets the form and order of messages and how each side understands them.

    من غير بروتوكول مشترك، يبقى الطرفان مثل شخصين يتكلمان لغتين مختلفتين.

    Without a shared protocol, the two sides are like two people speaking different languages.

    النص التشعبي Hypertext: نص فيه روابط تنقلك إلى نصوص أخرى، ومنه جاء اسم HTTP.

    Hypertext: text with links that take you to other texts; HTTP gets its name from it.

  15. الصفحة 15 من 40

    نص الصفحة 15

    ‏HTTP (HyperText Transfer Protocol)‎ بروتوكول نقل النص التشعبي: يحدد كيف يكتب العميل طلبه والخادم استجابته على الويب.

    HTTP (HyperText Transfer Protocol): the protocol that sets how the client writes requests and the server writes responses on the web.

    صفتان مهمتان في HTTP

    Two important features of HTTP

    الرسائل تنتقل مكشوفة؛ فمن يعترضها في الطريق يستطيع قراءتها.

    Messages travel in plain text, so anyone who intercepts them on the way can read them.

    عديم الحالة Stateless: كل طلب مستقل، والخادم لا يتذكر الطلب السابق بنفسه.

    Stateless: each request stands alone, and the server does not remember the previous request by itself.

    4. هل الكلام سري؟ HTTPS وTLS

    4. Is the Talk Private? HTTPS and TLS

    ‏HTTPS (HTTP Secure)‎: هو HTTP نفسه، بالطلبات والاستجابات نفسها، لكنها تمر داخل نفق آمن يصنعه TLS.

    HTTPS (HTTP Secure): the same HTTP, with the same requests and responses, but they pass through a secure tunnel made by TLS.

    علامته: يبدأ العنوان بـ https://‎، وتعرض بعض المتصفحات رمز قفل.

    Its sign: the address begins with https://, and some browsers show a padlock icon.

    ‏HTTP: مكشوف

    HTTP: open

    ‏HTTPS: نفق آمن

    HTTPS: secure tunnel

  17. الصفحة 17 من 40

    نص الصفحة 17

    ‏TLS (Transport Layer Security)‎ أمان طبقة النقل: بروتوكول أمان يقدم ثلاث حمايات:

    TLS (Transport Layer Security): a security protocol that gives three protections:

    السرية Confidentiality: تُشفَّر البيانات، فلا يقرؤها المتجسس.

    Confidentiality: the data is encrypted, so an eavesdropper cannot read it.

    السلامة Integrity: إذا عدّل أحد البيانات في الطريق، يُكتشف التعديل.

    Integrity: if someone changes the data on the way, the change is detected.

    المصادقة Authentication: تتأكد أنك تتصل بالخادم الحقيقي، عن طريق الشهادة الرقمية التي يقدمها.

    Authentication: you make sure you are talking to the real server, through the digital certificate it presents.

  18. الصفحة 18 من 40

    نص الصفحة 18

    التشفير Encryption: تحويل البيانات إلى صورة غير مفهومة، لا يعيدها إلى أصلها إلا من يملك المفتاح.

    Encryption: turning data into an unreadable form that only someone with the key can turn back.

    المتجسس Eavesdropper: أي طرف في الطريق يحاول قراءة الرسائل أو تعديلها، مثل شبكة Wi-Fi عامة غير آمنة.

    Eavesdropper: any party on the way that tries to read or change the messages, such as an unsafe public Wi-Fi network.

    معلومة تميزك

    EXTRA INSIGHT

    ‏SSL اسم قديم لبروتوكول سبق TLS وأُلغي لثغراته. الناس ما زالوا يقولون «شهادة SSL»، لكن الصحيح اليوم TLS.

    SSL is an old protocol before TLS, retired for its weaknesses. People still say “SSL certificate,” but today it is TLS.

    ثلاثة منكم: عميل، وخادم، وزميل في المنتصف هو «الشبكة».

    5. ماذا يريد العميل؟ GET وPOST

    5. What Does the Client Want? GET and POST

    طريقة طلب HTTP (HTTP Method): كلمة في أول كل طلب تحدد نوع العملية المطلوبة؛ إنها «الفعل» في جملة الطلب.

    HTTP method: a word at the start of every request that sets the kind of operation wanted; it is the “verb” of the request.

    ‏GET: لطلب مورد أو بيانات من الخادم، ولا يُفترض أن يغيّر شيئًا عليه. وأي معلومات إضافية تُكتب في العنوان URL نفسه، فتظهر في شريط العنوان.

    GET: requests a resource or data from the server and is not meant to change anything on it. Any extra information is written in the URL itself, so it shows in the address bar.

  21. الصفحة 21 من 40

    نص الصفحة 21

    ‏POST: لإرسال بيانات إلى الخادم ليعالجها، وغالبًا يتغير بسببها شيء عليه، مثل إنشاء حساب. والبيانات تُرسل في جسم الطلب، لا في العنوان.

    POST: sends data to the server to process, which often changes something on it, such as creating an account. The data goes in the request body, not in the URL.

    Just so you know: there are other methods, such as PUT to update and DELETE to delete.

    فخ امتحان

    EXAM TRAP

    ‏«POST آمن لأن بياناته لا تظهر في العنوان» خطأ. بيانات POST تنتقل مكشوفة إذا كان الاتصال HTTP؛ الحماية تأتي من HTTPS، لا من الطريقة.

    “POST is safe because its data is not in the URL” is wrong. POST data travels in plain text over HTTP; protection comes from HTTPS, not from the method.

    The first digit is the key: it tells you the family.

    ‏200‎ OK: تمت معالجة الطلب بنجاح.

    200 OK: the request was processed successfully.

    ‏404‎ Not Found: المورد المطلوب غير موجود بهذا العنوان، مثل عنوان مكتوب خطأ أو صفحة محذوفة. والخادم سليم، وهو الذي ردّ عليك.

    404 Not Found: the requested resource is not at this URL, such as a mistyped address or a deleted page. The server is working; it is the one that replied.

    ‏500‎ Internal Server Error: خطأ داخل الخادم منعه من إكمال الطلب. قد يكون طلبك سليمًا، والرمز وحده لا يحدد السبب.

    500 Internal Server Error: an error inside the server stopped it from completing the request. Your request may be fine; the code alone does not give the cause.

    7. من أي نافذة؟ واجهة برمجة التطبيقات (API)

    7. Through Which Window? The API

    واجهة برمجة التطبيقات API (Application Programming Interface): عقد أو مجموعة قواعد محددة تسمح لبرنامج أن يطلب بيانات أو خدمات من برنامج آخر، دون أن يعرف كيف يعمل من الداخل. وهي تحدد:

    API (Application Programming Interface): a contract or set of defined rules that lets one program request data or services from another, without knowing how it works inside. It defines:

    ما الطلبات المسموحة.

    Which requests are allowed.

    بأي شكل تُكتب.

    How they must be written.

    ماذا سيعود في الرد.

    What comes back in the reply.

    8. بأي شكل تأتي البيانات؟ JSON

    8. In What Shape Does Data Come? JSON

    ‏JSON (JavaScript Object Notation): صيغة نصية لكتابة البيانات بشكل منظم، يسهل على الإنسان قراءتها وعلى الحاسوب معالجتها.

    JSON (JavaScript Object Notation): a text format for writing data in an organized way that is easy for people to read and for computers to process.

    معلومة تميزك

    EXTRA INSIGHT

    رغم أن اسمها فيه JavaScript، فـ JSON ليست لغة برمجة، وتستخدمها لغات كثيرة جدًا.

    Even though its name contains JavaScript, JSON is not a programming language, and many languages use it.

  29. الصفحة 29 من 40

    نص الصفحة 29

    الكائن Object: بين قوسين متعرجين { }، وفيه أزواج من مفتاح وقيمة.

    Object: inside curly braces { }, holding key-value pairs.

    المفتاح Key: اسم الخانة، ويُكتب دائمًا بين علامتي تنصيص مزدوجتين، مثل "city".

    Key: the name of the field, always written in double quotes, such as "city".

    القيمة Value: محتوى الخانة: نص مثل "Cairo"، أو رقم مثل 31، أو true/false، أو null، أو كائن آخر، أو مصفوفة.

    Value: the field's content: text such as "Cairo", a number such as 31, true/false, null, another object, or an array.

    المصفوفة Array: قائمة قيم بين قوسين مربعين، مثل ["math", "physics"].

    Array: a list of values inside square brackets, such as ["math", "physics"].

    النقطتان : بين المفتاح والقيمة، والفاصلة , بين كل زوج والذي يليه.

    A colon : goes between a key and its value, and a comma , goes between one pair and the next.

    رحلة نقرة واحدة

    The Journey of One Click

    كل ما تعلمته يحدث في أقل من ثانية. تابع الرحلة؛ فهي نفسها إجابة سؤال «اشرح خطوة بخطوة»، وكل خطوة درجة.

    All you learned happens in under a second. Follow the journey; it is your answer to “explain step by step,” and each step is one mark.

    1 المتصفح هو العميل، ويبدأ الاتصال حين تكتب العنوان أو تنقر رابطًا.

    1 The browser is the client; it starts the communication when you type an address or click a link.

    2 يرسل العميل طلب HTTP إلى الخادم عبر الشبكة.

    2 The client sends an HTTP request to the server across the network.

    3 يحتوي الطلب على الطريقة GET، لأن المطلوب استرجاع صفحة، ومعها عنوان المورد.

    3 The request carries the GET method, since a page is wanted, plus the resource's URL.

    4 يستقبل الخادم الطلب، ويعالجه، ويبحث عن الصفحة.

    4 The server receives the request, processes it, and looks for the page.

    5 يعيد الخادم استجابة تحتوي على محتوى الصفحة، مثل HTML.

    5 The server returns a response containing the page content, such as HTML.

    6 تحمل الاستجابة رمز حالة: 200 إذا نجح الطلب، أو 404 إذا لم يوجد المورد. ثم يعرض المتصفح الصفحة.

    6 The response carries a status code: 200 for success or 404 for not found. Then the browser shows the page.

    لتميّز إجابتك: لو الاتصال HTTPS، تنتقل الرسائل مشفرة عبر TLS.

    To stand out: if the connection is HTTPS, the messages travel encrypted through TLS.

    حيل التذكر

    Memory Tricks

    ‏GET = «جيب»: يعني هات حاجة. POST = «بوسطة»: يعني ابعت حاجة.

    GET = “bring”: get me something. POST = “post”: send something, like mail.

    حرف S في HTTPS = Secure = سرّ. «حرف S بيقفل الظرف».

    The S in HTTPS = Secure. “The S seals the envelope.”

    الأرقام: «2 تمام، 4 غلطتك، 5 غلطتي». والمتكلم هنا هو الخادم.

    The codes: “2 all good, 4 your mistake, 5 my mistake”; the server is the one speaking.

    404: “Flat 404 is not in the building. The building is fine; the address you asked for is wrong.”

    فخاخ الامتحان

    Exam Traps

    هذه أشهر سبعة أخطاء يقع فيها الطلاب. اعرفها مرة، ولن تقع فيها أبدًا.

    These are the seven most common student mistakes. Know them once, and you will never fall for them.

    فخ امتحان

    EXAM TRAP

    ‏1 «POST آمن لأنه لا يظهر في العنوان» خطأ؛ الحماية تأتي من HTTPS، لا من الطريقة.

    1 “POST is safe because it is not in the URL” is wrong; protection comes from HTTPS, not the method.

  37. الصفحة 37 من 40

    نص الصفحة 37

    فخ امتحان

    EXAM TRAP

    ‏2 «404 معناها أن الخادم معطل» خطأ؛ الخادم يعمل وهو الذي ردّ عليك، والمشكلة في الطلب.

    2 “404 means the server is down” is wrong; the server is working and replied to you; the problem is in the request.

    فخ امتحان

    EXAM TRAP

    ‏3 «HTTPS بروتوكول مختلف تمامًا عن HTTP» خطأ؛ هو HTTP نفسه عبر اتصال TLS آمن.

    3 “HTTPS is a completely different protocol from HTTP” is wrong; it is the same HTTP over a secure TLS connection.

    فخ امتحان

    EXAM TRAP

    ‏4 «JSON لغة برمجة» خطأ؛ هي صيغة بيانات نصية.

    4 “JSON is a programming language” is wrong; it is a text data format.

    فخ امتحان

    EXAM TRAP

    ‏5 «API برنامج أو لغة» خطأ؛ هي واجهة، أي مجموعة قواعد للتواصل بين البرامج.

    5 “An API is a program or a language” is wrong; it is an interface, a set of rules for programs to communicate.

    فخ امتحان

    EXAM TRAP

    ‏6 «العميل هو الإنسان المستخدم» خطأ؛ العميل هو البرنامج، أي المتصفح أو التطبيق.

    6 “The client is the human user” is wrong; the client is the program, the browser or app.

    فخ امتحان

    EXAM TRAP

    ‏7 «GET لإرسال البيانات» خطأ؛ GET لطلب البيانات، وPOST لإرسالها لتُعالج.

    7 “GET is for sending data” is wrong; GET requests data, and POST sends data to be processed.
