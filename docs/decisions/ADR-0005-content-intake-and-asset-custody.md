# ADR-0005: إدخال المحتوى وحراسة الأصول وجرد الدروس

## Status

Accepted

## Context

اعتمد `ADR-0003` معمارية نشر الدروس بوصفها مستندات HTML ثابتة تعرض ملفات SVG مستقلة عبر `<img>`، واعتمد `ADR-0004` المعرّفات التقنية والمسارات الدائمة وقاعدة اشتقاق أسماء أصول الصفحات من مسار الدرس.

المستودع العام `parmaga` هو مصدر GitHub Pages الحالي، ويُخدم جذر فرع `main` كاملًا على النطاق العام. ملفات `docs/` نفسها قابلة للوصول عبر الويب. لذلك لا يمثل `main` منطقة تجهيز خاصة؛ إدخال أصل إليه يعني إدخاله إلى مسار النشر.

توجد الأصول الأصلية خارج المستودع العام، وتُنتج بعد Sessions أوفلاين متكررة. يجب حفظها دون تعديل، مع إثبات هويتها بالبايت، وفحصها وجردها قبل النشر، دون تمرير مكتبة SVG إلى نموذج ذكاء اصطناعي أو الاعتماد على أسماء الملفات وحدها بوصفها دليل سلامة.

الدرس المرجعي الأول هو:

```text
Course: programming-ai-baccalaureate-2
Term: term-1
Chapter: chapter-01
Lesson: lesson-01
```

ومساره الدائم المستقبلي:

```text
/courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/
```

ومسار أصوله المشتق:

```text
/assets/lessons/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/
```

يتكون الدرس المرجعي من 22 صفحة: صفحة افتتاحية واحدة و21 صفحة محتوى. أكد مالك المشروع ترتيبها من `page-001` إلى `page-022`، واستبعد مجموعة «شرح المدرس» نهائيًا من العرض والنشر.

تحدد برومبتات توليد الأصول مقاسًا قدره `1080×1350` بنسبة `4:5`، مع حجز آخر 12% من الصفحة فارغًا. لا يكفي وجود هذه القيم في البرومبتات؛ يجب التحقق منها عند الجرد.

## Decision

### 1. حراسة الأصول الأصلية

تُحفظ الأصول الأصلية في مستودع GitHub خاص مستقل اسمه:

```text
parmaga-content
```

لا يُفعّل GitHub Pages على ذلك المستودع.

توجد ثلاث نسخ مستقلة على الأقل:

1. النسخة المحفوظة في المستودع الخاص `parmaga-content`.
2. نسخة العمل المحلية.
3. نسخة أوفلاين مستقلة لا تعتمد على GitHub أو جهاز العمل وحده.

لا تصبح تسمية الملف أو وجوده في المستودع الخاص دليلًا على سلامته. تظل البصمة والجرد والفحص مطلوبة.

### 2. حراسة ملفات السياق الخاصة

تُحفظ في `parmaga-content`، ولا تدخل المستودع العام:

- أرشيف برومبتات التوليد.
- ملفات Markdown المجمعة للدروس.
- أي مواد داخلية غير معتمدة للنشر العام.
- مجموعة «شرح المدرس» إن ظلت محفوظة لأغراض داخلية.

السبب هو أن `docs/` في المستودع العام تُقدّم فعليًا على النطاق العام، ولا يجوز اعتبارها مساحة خاصة.

يجوز إدخال Context Packet المخصص للتسليم إلى `docs/content/context/` لأنه ملخص جرد معتمد للنشر العام، لا نسخة من البرومبتات أو الملفات المجمعة.

### 3. قاعدة الحاجز بين الجرد والنشر

لا يدخل أي أصل SVG إلى `main` قبل اكتمال:

- الترتيب.
- إعادة التسمية القانونية.
- حساب البصمات.
- قراءة الأبعاد.
- تحليل XML.
- فحص العناصر والمراجع الأمنية.
- مراجعة النتائج.
- اكتمال Manifest الدرس.

بعد ذلك لا يدخل الأصل إلى `main` إلا داخل commit نشر الدرس نفسه.

لا يُنشأ commit تجهيز سابق يحتوي الأصول وحدها. السبب الحاكم:

```text
main = نشر
```

ملفات الجرد والتوثيق في هذه المرحلة لا تنشر الدرس، ولا يجوز أن تحتوي أي أصل SVG.

### 4. رفض Git LFS للأصول المنشورة

لا يُستخدم Git LFS للنسخة التي ستخدمها GitHub Pages.

GitHub Pages لا يقدم أصول LFS المنشورة بوصفها الملفات الأصلية في هذا الاستخدام، وقد يقدم ملف Pointer نصيًا بدل الأصل. كما أن أحجام الأصول الحالية، التي تدور حول 15 KB للملف، لا توفر مبررًا تقنيًا لاستخدام LFS.

يمكن إعادة تقييم تخزين الأصول الخاصة مستقبلًا بقرار مستقل، لكن النسخة المنشورة لا تعتمد على Git LFS.

### 5. إغلاق قرار «شرح المدرس»

مجموعة «شرح المدرس» مستبعدة نهائيًا من العرض والنشر بقرار مالك المشروع.

يوجد لكل درس تسلسل صفحات واحد فقط. لا يضاف نوع أصول أو مستوى مسار أو فرع تسمية لهذه المجموعة.

إعادة فتح هذا القرار تحتاج ADR مستقلًا قبل أي تنفيذ. لا تعد إعادة فتحه تحديث محتوى عاديًا.

### 6. صيغة Manifest

تكون صيغة Manifest:

- JSON.
- ملفًا واحدًا لكل درس.
- UTF-8 بلا BOM.
- بنهايات أسطر LF.
- صالحة للتحليل بأداة JSON قياسية.

رُفض YAML لأن حساسيته للمسافات وأنواعه الضمنية تزيد احتمالات الخطأ اليدوي. ورُفض CSV لأنه غير مناسب للبنية المتداخلة والمصفوفات ونتائج الفحص. ورُفض Markdown لأنه مستند عرض لا صيغة بيانات صارمة. كما رُفض الاحتفاظ بتمثيلين متزامنين للمعلومات نفسها لأن ذلك ينشئ مصدرَي حقيقة قابلين للـDrift.

Manifest JSON هو مصدر الحقيقة المنظم للجرد. Context Packet تمثيل تسليم مختصر مشتق منه، وليس Manifest ثانيًا.

### 7. مخطط Manifest

رقم المخطط الأول هو:

```text
1
```

حقول مستوى الدرس:

- `schemaVersion`: رقم مخطط Manifest.
- `course`: معرّف Course المعتمد.
- `term`: معرّف Term المعتمد.
- `chapter`: معرّف Chapter المعتمد.
- `lesson`: معرّف Lesson المعتمد.
- `displayTitleAr`: عنوان العرض العربي.
- `displayTitleEn`: عنوان العرض الإنجليزي المعتمد.
- `permanentPath`: المسار الدائم للدرس.
- `assetBasePath`: مسار مجلد الأصول المنشور.
- `status`: حالة الجرد؛ القيمة الحالية `inventoried`.
- `inventoryDate`: تاريخ الجرد بصيغة `YYYY-MM-DD`.
- `checksumAlgorithm`: خوارزمية البصمة؛ القيمة `sha256`.
- `declaredPageCount`: عدد الصفحات المعلن.
- `notes`: ملاحظات الدرس.
- `pages`: مصفوفة صفحات الدرس بالترتيب المعتمد.

حقول كل صفحة:

- `id`: معرّف الصفحة دون الامتداد.
- `file`: اسم الملف القانوني.
- `sourceFileName`: اسم الملف الذي فُحص في مصدر الجرد.
- `order`: ترتيب الصفحة المعتمد.
- `role`: إما `opening` أو `content`.
- `sha256`: بصمة بايتات الملف.
- `bytes`: حجم الملف بالبايت.
- `width`: قيمة عرض عنصر الجذر.
- `height`: قيمة ارتفاع عنصر الجذر.
- `viewBox`: قيمة `viewBox`.
- `encoding`: الترميز الذي أثبته الفحص.
- `xmlWellFormed`: نتيجة تحليل XML.
- `textElementCount`: عدد عناصر `text`.
- `fontsReferenced`: أسماء الخطوط المستدعاة.
- `security`: نتائج الفحص الأمني.
- `descriptionAr`: وصف عربي من سطر واحد.

حقول `security`:

- `hasScript`: وجود `script`.
- `hasForeignObject`: وجود `foreignObject`.
- `hasEventHandlers`: وجود سمات أحداث `on*`.
- `hasExternalHttpRef`: وجود مرجع HTTP أو HTTPS خارجي فعلي، مع استبعاد URI مساحة الأسماء القياسية.
- `hasDataUri`: وجود `data:`.
- `hasEmbeddedImage`: وجود عنصر `image`.
- `hasStyleImport`: وجود `@import` داخل `style`.
- `findings`: الاكتشافات وقراراتها المكتوبة.

إذا تعذر الحصول على قيمة، تكون `null` ويُكتب سبب النقص في `findings` أو `notes` بحسب نطاقه. لا تُقدّر القيم ولا تُخترع.

### 8. البصمات والتحقق الثلاثي

الخوارزمية المعتمدة هي SHA-256 على بايتات الملف كما هي.

تُتحقق البصمة في ثلاث نقاط:

1. قبل commit النشر، من النسخة القانونية المحلية.
2. بعد commit النشر، من الملف المستخرج أو المقروء من Git دون تعديل.
3. بعد النشر، من بايتات الاستجابة الحية للأصل.

يجب أن تتطابق القيم الثلاث حرفيًا. أي اختلاف يوقف الإغلاق ويُحقق فيه قبل توسيع النشر.

### 9. الفحص الأمني

يشمل الفحص، على الأقل:

- `script`.
- `foreignObject`.
- سمات الأحداث `on*`.
- `javascript:`.
- مراجع HTTP أو HTTPS الخارجية.
- `data:`.
- عناصر `use` ذات المراجع الخارجية.
- `image`.
- `iframe`.
- `embed`.
- `object`.
- `@import` داخل `style`.

URI القياسي لمساحة أسماء SVG ليس مرجعًا شبكيًا خارجيًا. يجب التمييز بين الاكتشاف اللفظي والمرجع القابل للتحميل.

كل اكتشاف يُسجل، ولكل اكتشاف قرار مكتوب. الخيارات هي القبول المعلل، أو رفض الأصل من النشر، أو الرجوع إلى مصدر التوليد لإنتاج أصل جديد. لا يُعالَج الاكتشاف بتعديل الأصل المفحوص أو تنظيفه أو إعادة تنسيقه.

في عينة الدرس المرجعي، التقط الفحص اللفظي `http://www.w3.org/2000/svg` في كل ملف. أثبت الفحص السياقي أنه URI مساحة أسماء قياسي فقط، دون مراجع سمات أو CSS أو مراجع شبكية متبقية. قُبلت الملفات من هذه الناحية وسُجل `hasExternalHttpRef` بالقيمة `false` دون تعديلها.

### 10. التسليم إلى نماذج الذكاء الاصطناعي

لا يُمرر أي ملف SVG إلى أي نموذج ذكاء اصطناعي.

يكون التسليم المعتاد بواسطة Context Packet الذي يحتوي معلومات الدرس والجرد والقيود والأوصاف، ويكون بديلًا كاملًا عن قراءة الأصول.

الاستثناء هو صفحة واحدة محددة عند وجود مشكلة لا يمكن تشخيصها من الجرد والسياق. يجب توثيق:

- الصفحة المحددة.
- المشكلة المحددة.
- سبب عدم كفاية Context Packet.
- النموذج أو الخدمة التي استلمتها.
- القرار الناتج.

لا يسمح الاستثناء بتمرير درس كامل أو مكتبة الأصول.

### 11. `.gitattributes`

يضاف ملف `.gitattributes` بقاعدة واحدة تمنع Git من تطبيع نهايات الأسطر لملفات SVG:

```gitattributes
*.svg -text
```

السبب هو الحفاظ على تطابق بايتات الأصل وصلاحية مقارنة SHA-256 قبل commit وبعده وبعد النشر.

لا تضاف قاعدة عامة مثل `* text=auto`، ولا قاعدة شاملة لـLF، لأن ذلك قد يغير معالجة ملفات قائمة خارج نطاق هذه المرحلة.

### 12. خصائص الأصول وطبقة HTML

الخصائص المطلوبة للأصول هي:

- عرض `1080`.
- ارتفاع `1350`.
- نسبة `4:5`.
- آخر 12% من الصفحة فارغ، أي المنطقة من `y=1188` إلى `y=1350` في نظام الإحداثيات الحالي.

تُقاس هذه الخصائص ولا تُفترض من برومبت التوليد.

تأتي من طبقة HTML حصرًا:

- هوية Parmaga.
- رقم الصفحة المرئي.
- التنقل.
- روابط الصفحات.
- النص الدلالي والوصف البديل.

يتفق ذلك مع `ADR-0004` §19. لا تعدّل ملفات SVG لإضافة هذه العناصر.

### 13. العلاقة مع القرارات السابقة

هذا القرار يكمل `ADR-0004` §18 ولا يعدله ولا يغير قاعدة تسمية الأصول أو شجرتها أو أي بند آخر فيه.

لا يعدل هذا القرار:

- `ADR-0001`.
- `ADR-0002`.
- `ADR-0003`.
- `ADR-0004`.

هذا قرار توثيقي وجردي فقط. لا ينشئ مسار نشر، ولا ينشر درسًا، ولا يضيف SVG إلى المستودع العام، ولا يعدل الموقع المنشور.

## Alternatives Considered

### 1. حفظ الأصول في المستودع العام قبل نشر الدرس

رُفض لأن `main` يُخدم علنًا، ولأن وجود الأصل في مسار قابل للتخمين قد ينشره قبل اكتمال الدرس والفهرسة والوصولية.

### 2. Git LFS

رُفض لأن GitHub Pages لا يخدم ملف LFS المنشور بالطريقة المطلوبة، ولأن أحجام الملفات الحالية صغيرة.

### 3. حفظ البرومبتات وملفات Markdown المجمعة تحت `docs/`

رُفض لأن `docs/` منشور علنًا على النطاق الحالي.

### 4. YAML أو CSV أو Markdown للـManifest

رُفضت لضعف الملاءمة أو الصرامة أو قابلية تمثيل البنية المتداخلة مقارنة بـJSON.

### 5. Manifest بصيغتين متزامنتين

رُفض لأنه ينشئ مصدرَي حقيقة ويزيد احتمال Drift.

### 6. تعديل SVG لإزالة الاكتشافات

رُفض لأن الأصل المفحوص يجب أن يبقى ثابت البايتات. عند وجود اكتشاف غير مقبول يُرفض الأصل أو يُعاد إنتاجه من المصدر.

### 7. تمرير SVG كاملة إلى نموذج ذكاء اصطناعي

رُفض لحماية الأصول وتقليل نقل المحتوى غير الضروري. Context Packet هو مسار التسليم الافتراضي.

## Consequences

### Positive

- تُحفظ الأصول الأصلية خارج منطقة النشر حتى commit الدرس.
- تصبح كل صفحة قابلة للتحقق ببصمة ثابتة.
- يمكن مراجعة الدرس دون قراءة ملفات SVG.
- تُفصل المواد الداخلية عن المستودع العام.
- تقل مخاطر تعديل الأصول دون اكتشاف.
- تُسجل نتائج الفحص والقرارات بصورة قابلة للمراجعة.
- لا يحتاج النظام إلى Dependency أو Build Step أو CI.
- لا يغير نظام المسارات المعتمد.

### Negative

- يحتاج كل درس إلى جرد ومراجعة يدوية.
- يتطلب النشر مقارنة بصمات في ثلاث نقاط.
- يحتاج Context Packet إلى تحديث عند تغير Manifest.
- يظل قياس المنطقة الفارغة خطوة تحقق مستقلة.
- يجب الاحتفاظ بنسخ متعددة ومراجعة سلامتها.
- اكتشاف أمني واحد قد يوقف أصلًا أو درسًا كاملًا حتى اتخاذ قرار.

## Implementation Boundary

تنفذ هذه المرحلة:

- هذا ADR.
- إجراء إدخال المحتوى.
- Manifest جرد للدرس المرجعي.
- Context Packet للدرس المرجعي.
- قاعدة `.gitattributes`.
- تحديث README.

لا تنفذ:

- `courses/`.
- `assets/lessons/`.
- أي SVG.
- `sitemap.xml`.
- صفحة درس.
- نص HTML تعليمي.
- وصفًا بديلًا.
- مراسي مفاهيم.
- JavaScript.
- Build Step.
- Dependency.
- CI.
- نشرًا أو Viewer.

## Rollback

قبل الدفع:

- تُحذف الملفات الخمسة الجديدة يدويًا.
- يُستعاد `README.md` باستخدام:

```text
git restore README.md
```

لا يُستخدم `reset --hard` أو `clean`.

بعد الدفع، يكون التراجع عبر:

```text
git revert <sha>
```

في commit عكسي واحد.

التراجع آمن في هذه المرحلة لأنه لا يوجد URL درس منشور ولا أصل SVG داخل المستودع العام يعتمد على هذه الوثائق.
