# ADR-0021 — طبقة بورد عائمة للكتابة الحرة فوق صفحة الدرس

## Status

Accepted — Owner-approved; implementation pending

## Context

يحتاج المدرّس أثناء عرض صفحة الدرس على شاشة لمس كبيرة إلى فتح طبقة بيضاء عائمة والكتابة والرسم عليها بالإصبع أساسًا، مع دعم القلم والماوس، ثم إخفائها والعودة إلى الدرس وإظهارها ثانيةً دون فقدان محتوى الجلسة.

النطاق المطلوب هو الكتابة الحرة، والممحاة، والتراجع، والإعادة، ومسح الكل. لا يشمل القرار الحفظ الدائم أو السحابي، أو التعاون، أو التصدير، أو الأشكال، أو النص بلوحة المفاتيح، أو تعدد صفحات البورد، أو التكبير والتحريك داخلها.

صفحة الدرس الحالية ثابتة وتعمل بلا JavaScript. ويجب أن يبقى ذلك صحيحًا: فشل تحميل مكوّن البورد أو تهيئته لا يجوز أن يحجب الدرس أو يترك زرًا ميتًا.

يحمل المستودع حاليًا ملفي JavaScript في صفحة الدرس:

- `assets/js/lesson-viewer.js`
- `assets/js/pwa-install.js`

لكن ADR-0007:75 وADR-0007:161 حصرا رفع منع JavaScript في ملف خارجي واحد هو `lesson-viewer.js`. وأجاز ADR-0019 لاحقًا `pwa-install.js` دون تعديل صريح لذلك القيد، مع تصريحه بأنه لا ينسخ ADR-0007. لذلك لا يجوز إضافة ملف ثالث بالسكوت أو القياس الضمني.

ويمنع ADR-0015 manifest وregistry وvendoring وCDN وpackage manager وbuild step. كما يمنع ADR-0019 إنشاء ملف CSS ثانٍ أو تعديل `lesson-viewer.js` لإتاحة مكوّن جديد.

لا يوجد token لـ`z-index`. وتستخدم أدوات عارض الدرس الطبقة 30، ويستخدم مكوّن الترويج الطبقة 20. أما كتلة الطباعة التي تبدأ بـ`@media print` في `assets/css/parmaga.css` فهي مجمّدة ومحروسة باختبار بايتّي وبصمة SHA-1.

## Decision

### D1 — نسخ محدود ومعلن لقيد الملف الخارجي الواحد

ينسخ هذا القرار، في نطاق صفحة الدرس وحدها، قيد «ملف خارجي واحد» الوارد في ADR-0007:75 وADR-0007:161.

تصير ملفات JavaScript المسموحة في صفحة الدرس ثلاثة ملفات مسماة حصرًا:

1. `assets/js/lesson-viewer.js`
2. `assets/js/pwa-install.js`
3. `assets/js/lesson-board.js`

لا ينشئ ذلك إذنًا عامًا بإضافة ملفات JavaScript أخرى. أي ملف رابع يحتاج قرار مالك مستقلًا.

تبقى سائر قيود ADR-0007 وADR-0015 نافذة: لا dependency ولا manifest ولا registry ولا vendoring ولا CDN ولا package manager ولا Router ولا build step.

### D2 — بصمة التنفيذ

بصمة التنفيذ الإنتاجية محصورة في:

1. ملف JavaScript جديد واحد هو `assets/js/lesson-board.js`.
2. قسم CSS معزول واحد داخل `assets/css/parmaga.css` بين علامتي `BEGIN lesson-board` و`END lesson-board`.
3. سطر `<script defer>` واحد في صفحة الدرس المرشحة.
4. جذر مكوّن واحد ينشئه JavaScript داخل `main` وبعد `.lesson-viewer-controls` في ترتيب الأشقاء.

يجوز إضافة أو تعديل الاختبارات العقدية وتحديث دفتر الأدلة وفق بروتوكول المشروع.

يُحظر:

- تعديل `assets/js/lesson-viewer.js`.
- إنشاء ملف CSS ثانٍ.
- تعديل أي قاعدة CSS قائمة لإتاحة المكوّن.
- قراءة `data-panel-open` أو كتابتها.
- إدراج جذر البورد أو زرها ثابتًا في HTML.
- تجاوز البصمة دون قرار مالك جديد.

### D3 — تحسين تدريجي وفشل صفري

لا يدرج `lesson-board.js` جذر المكوّن أو زر فتحه قبل التحقق من العناصر والقدرات اللازمة واكتمال التهيئة.

إذا فشلت التهيئة بعد بدء الإدراج، يزيل المكوّن الآثار التي أنشأها هو. ولا يغير محتوى الدرس الأصلي أو يخفيه.

عند فشل تحميل الملف أو عدم تشغيل JavaScript يبقى الدرس ثابتًا وكاملًا، ولا يظهر زر ميت أو حجز بصري خاص بالبورد.

### D4 — Canvas ونموذج البيانات

يستخدم المكوّن Canvas كسطح عرض.

ولا يكون bitmap وحده مصدر الحقيقة؛ بل يحتفظ المكوّن في الذاكرة بنموذج strokes وأوامر الجلسة لإتاحة:

- التراجع والإعادة.
- إعادة الرسم بعد تغيير الحجم أو الاتجاه.
- إعادة إظهار الطبقة دون فقدان المحتوى.
- إعادة بناء السطح بعد مسح Canvas عند تغيير أبعاده.

لا تُنشأ Canvas ثانية كاملة الحجم للتاريخ أو التخزين المؤقت.

### D5 — الاستيحاء الخوارزمي دون نقل

يكون التنفيذ مستقلًا بأسلوب المشروع، مستوحيًا مفاهيميًا من الخوارزميات المنشورة للتنعيم بمنحنيات spline أو Bézier وبناء خط متغير العرض.

يجوز الاستفادة من الأفكار المنشورة الآتية:

- تنعيم العينات بدل وصلها بخطوط خام.
- استعمال ضغط القلم الحقيقي عندما يكون صالحًا.
- استعمال سرعة الحركة بديلًا عندما يكون الضغط غائبًا أو غير مفيد.
- الرسم التزايدي وتجنب إعادة بناء التاريخ في كل حركة.

لا تُنسخ شيفرة من `perfect-freehand` أو `signature_pad` أو `atrament`، ولا تُدرج أي منها dependency أو vendored source أو CDN.

### D6 — الإصبع هو مسار الإدخال الأساسي

الرسم والكتابة بالإصبع Requirement أساسي وليس fallback.

يدعم المكوّن:

- `pointerType="touch"` للرسم بالإصبع.
- `pointerType="pen"` للرسم بالقلم.
- `pointerType="mouse"` للاستخدام المكتبي والاختبار.

يلتقط سطح الرسم المؤشر النشط حتى لا تنقطع الضربة بسبب الحركة السريعة أو الخروج المؤقت من حدوده.

تُستخدم coalesced events عند توفرها، مع fallback إلى أحداث المؤشر العادية.

### D7 — الضغط وعرض الخط

إذا قدم الجهاز ضغطًا متغيرًا ذا معنى، يجوز استعماله بعد التنعيم والحدود الآمنة.

لا يُفترض أن ضغط touch موثوق أو متغير. وعندما يكون غائبًا أو ثابتًا أو غير مفيد، يُشتق عرض الخط من سرعة الحركة بعد تنعيمها.

يجب ألا تنتج قيمة ضغط صفرية أو ثابتة خطًا غير مرئي أو عرضًا معطوبًا.

### D8 — راحة الكف وتعدد اللمس

لأن المتصفح قد يبلغ الإصبع وراحة الكف كلاهما بوصفهما `touch`، فإن رفض راحة الكف best-effort وليس ضمانًا مطلقًا.

تعتمد السياسة الآتية:

- أول touch أساسي صالح يبدأ الضربة.
- أي touch إضافي أثناء الضربة لا يبدأ ضربة أخرى.
- لا يستخدم تعدد اللمس للرسم.
- تستخدم `isPrimary` وحالة المؤشرات ومساحة التلامس قرائن لرفض اللمسات غير المرغوبة.
- لا تستخدم `width` أو `height` منفردتين بوصفهما حقيقة قاطعة.
- عند نشاط قلم تكون له الأولوية وتُرفض لمسات touch المصاحبة.
- تعاير حدود مساحة التلامس على البورد المستهدفة قبل إغلاق التنفيذ.

اختبار إصبع وراحة كف فعلي على الشاشة المستهدفة شرط قبول؛ ولا تكفي محاكاة DevTools.

### D9 — التمرير والتكبير

يمنع سطح Canvas pan والتمرير وpinch الخاص بالمتصفح أثناء فتح البورد والتفاعل مع سطح الرسم.

لا يُعطل zoom على الموقع أو صفحة الدرس عمومًا، ولا تعدل إعدادات viewport. وبعد إخفاء البورد يعود تمرير الدرس وتكبيره إلى سلوكهما الطبيعي.

توضع أدوات البورد خارج مساحة Canvas التفاعلية، بحيث يكون لمس زر الأداة تفاعلًا مع زر ولا ينشئ نقطة رسم.

### D10 — الحوار والتركيز

تعرض البورد داخل native modal dialog في top layer.

يترتب على ذلك:

- لا يحتاج سطح البورد إلى `z-index`.
- ينتقل التركيز عند الفتح إلى أداة مناسبة داخل الحوار.
- يخفي Escape البورد دون مسح محتواها.
- يعيد الإغلاق التركيز إلى زر الفتح.
- لا تدخل الصفحة الخلفية في ترتيب التركيز أثناء فتح الحوار.
- لا ينشأ فخ تركيز يدوي إذا كان السلوك الأصلي للحوار كافيًا.
- لا ينسق المكوّن حالته مع `data-panel-open`.

### D11 — زر الفتح وغياب token للطبقات

لا يضيف التنفيذ قيمة `z-index` جديدة لزر فتح البورد، ولا يعيد استعمال الطبقتين 20 أو 30 باجتهاد.

يوضع الزر بخصائص منطقية في موضع لا يتقاطع مع أدوات العارض أو مكوّن الترويج أو الحجز السفلي القائم.

إذا أثبت التنفيذ أن الزر يحتاج طبقة جديدة، يتوقف التنفيذ ويعود القرار إلى المالك. ولا يحل ذلك بقيمة خام داخل PR التنفيذ.

يبقى إنشاء ADR رموز شامل لـ`z-index` متابعة مؤجلة.

### D12 — التاريخ داخل الجلسة

كل ضربة رسم أمر مستقل، وكل ضربة محو أمر مستقل.

يكون «مسح الكل» أمرًا قابلًا للتراجع، ولا يحتاج مربع تأكيد إضافيًا.

ينقل Undo آخر أمر إلى redo. وأي رسم أو محو جديد بعد Undo يلغي فرع redo.

إخفاء البورد وإعادة إظهارها لا يمسحان التاريخ. أما إعادة تحميل الصفحة فتنهي الجلسة وتمسح محتوى البورد.

لا يستخدم المكوّن localStorage أو IndexedDB أو Cache API أو Service Worker أو أي حفظ دائم أو شبكي.

### D13 — تغيير الحجم والاتجاه

تكون بيانات strokes مصدر الحقيقة عند تغير حجم النافذة أو اتجاه الجهاز.

يعاد إنشاء أبعاد Canvas وإعادة رسم المحتوى من البيانات، مع تحجيم موحد يحافظ على النسبة ولا يشوه الكتابة أفقيًا أو رأسيًا.

لا تفقد عمليات undo وredo بسبب تغيير الحجم.

لا يعاد رسم التاريخ كاملًا في كل `pointermove`. ويقتصر replay الكامل على undo وredo ومسح الكل وتغيير الحجم أو الاتجاه.

### D14 — DPI وسقف الذاكرة

يراعي Canvas `devicePixelRatio` مع سقف للـbacking store قدره `8,294,400` بكسل.

عند تجاوز السقف يخفض المكوّن DPR الفعال مع إبقاء القياسات المنطقية ونموذج strokes دون تغيير.

لا يضمن هذا القرار الحدة القصوى على كل تركيب ممكن من حجم viewport وDPR، بل يوازن الحدة مع منع استهلاك ذاكرة غير محدود.

### D15 — الأداء والوزن

لا يتجاوز حجم `assets/js/lesson-board.js` مقدار 24 KiB غير مضغوط.

يكون الرسم أثناء حركة المؤشر تزايديًا، وتجمع العينات المتاحة للرسم مرة واحدة لكل إطار عرض بدل تنفيذ عمل كامل لكل حدث منفرد.

يجب وضع حدود معلنة لعدد نقاط الضربة وإجمالي نقاط الجلسة. وعند بلوغ حد الجلسة يتوقف قبول strokes جديدة برسالة حالة، دون حذف الرسوم السابقة أو تعطيل الدرس.

لا توصف نتائج CLS أو LCP أو INP بأنها Confirmed قبل القياس. ويبقى أثرها Unknown حتى بوابة تحقق مستقلة. ولا يحل هذا القياس محل E13 ولا يغلقها أو يستبدلها.

### D16 — الوصول وRTL

تستخدم أدوات التحكم عناصر `button` حقيقية، ولا يقل هدف اللمس عن `--pg-touch-target`.

تُورث قاعدة `:focus-visible` العامة ثنائية الطبقة، ولا تستبدل بقاعدة محلية أضعف.

توفر الأدوات أسماء عربية واضحة للرسم والممحاة والتراجع والإعادة ومسح الكل وإخفاء البورد. وتعرض حالات Undo وRedo المعطلة دلاليًا وبصريًا.

تستخدم الواجهة الخصائص المنطقية. أما إحداثيات Canvas فهي فيزيائية نسبة إلى مستطيله ولا تعكس بسبب `dir="rtl"`، ولا يستخدم transform لعكس السطح.

لا يضيف المكوّن animation أو transition، وبذلك يبقى صالحًا مع `prefers-reduced-motion` دون حركة زخرفية.

### D17 — الطباعة

يكون جذر البورد ومحدداته مخفيًا افتراضيًا، ويقتصر إظهاره على `@media screen`.

لا ينشئ قسم المكوّن `@media print` جديدة، ولا يعدل أي بايت من كتلة الطباعة المجمدة التي تبدأ بـ`@media print` في نهاية `assets/css/parmaga.css`.

تبقى بصمة كتلة الطباعة وطولها المحروسان بالاختبار دون تغيير.

### D18 — الحجز السفلي وCLS

لا ينشئ المكوّن حجزًا سفليًا رابعًا في صفحة الدرس.

زر الفتح والحوار خارج تدفق محتوى الدرس، ولذلك يجب ألا يؤدي ظهورهما إلى تغيير موضع عناصر الدرس المرئية.

هذا تقدير هندسي فقط. وتبقى نتيجة CLS الفعلية Unknown حتى القياس.

### D19 — الاختبارات العقدية

يجب أن تغطي العقود، على الأقل:

- الملف الجديد وسطر `defer` الوحيد.
- عدم تعديل `lesson-viewer.js`.
- عدم إنشاء ملف CSS ثانٍ.
- عزل قسم CSS بين BEGIN وEND.
- غياب `@media print` من القسم.
- غياب `data-panel-open`.
- غياب dependencies وCDN والتخزين وService Worker.
- سقف حجم JavaScript.
- بقاء بصمة كتلة الطباعة.
- غياب جذر بورد ثابت من HTML.
- التهيئة التدريجية بلا زر ميت.
- الرسم بالإصبع والقلم والماوس.
- رفض touch إضافي أثناء الضربة.
- Undo وRedo والممحاة ومسح الكل.
- الاحتفاظ بالمحتوى عند الإخفاء وإعادة الإظهار.
- إعادة الرسم عند تغيير الحجم.
- RTL والتركيز وحد اللمس.

أي تعديل لنص ADR محروس يجب أن يعدل عقده صراحة في المرحلة نفسها، مع حفظ عرف CRLF للملفات المحروسة.

### D20 — بوابات التوقف

يتوقف التنفيذ ولا يجتهد إذا احتاج إلى:

- تعديل `lesson-viewer.js`.
- قراءة `data-panel-open` أو كتابتها.
- قيمة `z-index` جديدة.
- تعديل قاعدة CSS قائمة.
- تعديل كتلة الطباعة.
- dependency أو manifest أو CDN أو vendoring أو build step.
- تجاوز 24 KiB لملف JavaScript.
- تغيير خارج البصمة المعتمدة.
- تعطيل zoom على الصفحة كلها.
- حفظ دائم أو شبكي.
- الادعاء بأن راحة الكف مضمونة دون اختبار الجهاز الفعلي.

## Consequences

### Positive

- تصبح الكتابة بالإصبع وظيفة أساسية بدل اعتمادها على وجود قلم متخصص.
- يبقى الدرس صالحًا بالكامل عند فشل JavaScript.
- لا تدخل dependency أو بنية بناء جديدة.
- يبقى المكوّن منفصلًا عن حالة `lesson-viewer.js`.
- يمكن التراجع عن التنفيذ بحذف بصمته المعزولة.
- يحتفظ المستخدم بالرسم خلال الإخفاء وإعادة الإظهار وتغيير الاتجاه داخل الجلسة.

### Negative

- تنفيذ التنعيم والتاريخ وإعادة الرسم يزيد مساحة المراجعة والصيانة.
- Canvas عالي DPI قد يستهلك ذاكرة كبيرة، ولذلك تفرض دقة فعالة محدودة عند تجاوز السقف.
- رفض راحة الكف مع قبول الإصبع لا يمكن ضمانه على جميع الأجهزة.
- التراجع في Canvas يحتاج replay للتاريخ في بعض العمليات.
- يضيف القرار استثناءً صريحًا جديدًا إلى قيد ملفات JavaScript في ADR-0007.

### Risks

- تفاوت جودة Pointer Events والضغط ومساحة التلامس بين أجهزة البورد.
- تدهور INP إذا لم تجمع العينات أو أعيد بناء التاريخ أثناء الحركة.
- استهلاك ذاكرة أو CPU غير محدود إذا غابت حدود النقاط والجلسة.
- تعارض موضع زر الفتح مع أدوات العارض على بعض الأحجام.
- اختلاف الإحساس بالخط بين الإصبع والقلم بسبب غياب ضغط touch موثوق.

## Verification

قبل إغلاق التنفيذ يجب:

1. تشغيل مجموعة اختبارات المشروع كاملة.
2. تشغيل `python3 tools/verify_lesson.py .`.
3. تشغيل فحص الفراغات المعتمد مع `core.whitespace=cr-at-eol`.
4. التحقق من حجم `lesson-board.js`.
5. التحقق من بصمة كتلة الطباعة وطولها.
6. اختبار الفشل مع عدم تحميل ملف البورد.
7. اختبار لوحة المفاتيح والتركيز وEscape.
8. اختبار RTL وتغيير الاتجاه والحجم.
9. اختبار خط طويل وUndo وRedo والممحاة ومسح الكل.
10. اختبار الكتابة بإصبع فعلي وراحة كف فعلية على البورد المستهدفة.
11. قياس CLS وLCP وINP مع إبقاء النتائج Unknown حتى توفر دليل القياس.

## Rollback

يكون سحب القرار التنفيذي عبر revert واحد لحزمة التنفيذ.

تتكون البصمة القابلة للسحب من:

- `assets/js/lesson-board.js`
- سطر التحميل في صفحة الدرس
