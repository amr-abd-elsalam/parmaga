# ADR-0014: دلالة عناصر تحكم العارض — ظل سكون وتحويم محروس وضغط داخلي

## Status

Accepted — 2026-09-05.

- Related: `ADR-0009` و`ADR-0010` و`ADR-0012` و`ADR-0013`.
- Does not amend: `ADR-0011` أو عقد الطباعة أو سلوك JavaScript أو بنية HTML.
- Implementation phase: 7.3.

هذا القرار معتمد للتنفيذ ضمن الحدود الواردة أدناه. ولا يمنح إذنًا لتعديل JavaScript أو HTML أو SVG أو أصول الدروس أو أدوات البناء أو سير العمل.

## Context

عناصر تحكم العارض الحالية قابلة للاستخدام بلوحة المفاتيح، ولها عقد `:focus-visible` قائم، وتستخدم ألوان وحدود الهوية المعتمدة. لكن الزر العائم لا يحمل في السكون ظل اللوحات القائم، كما أن تحويم أزرار العارض غير محروس بقدرة الجهاز على التحويم الدقيق، ولا توجد حالة ضغط داخلية صريحة للزر العائم وأزرار اللوحة.

أثبت الفحص المتصفحي الذي أرسله المالك بعد التنفيذ الأول أن إضافة الظل وحدها غير كافية: كلمتا «صفحات» و«كتابة» ظهرتا محشورتين داخل دائرتين ثابتتين بعرض وارتفاع 44px ونص 0.75rem، فبدتا كمؤشرين صغيرين لا كأزرار تفاعل واضحة. ورفض المالك النتيجة البصرية صراحة، لذلك لا يُعد التنفيذ الأول مقبولًا رغم نجاح فحوصه الساكنة.

المطلوب دلالة بصرية واضحة في السكون نفسه، لا دلالة لا تظهر إلا عند التحويم أو الضغط. لذلك يصبح FAB زرًا نصيًا Pill بعرض يتبع النص، مع بقاء الحد الأدنى لهدف اللمس، وحشو وحجم خط من الرموز القائمة. والنمط القائم في `.button:active` يوفر السابقة المناسبة للضغط: حد أوضح، وظل داخلي، وتسطير، بلا حركة أو تحويل.

كتلة الطباعة محكومة بـ`ADR-0011` ومجمدة. لذلك يجب أن يسبق كل CSS جديد كتلة `@media print` وألا يتغير أي سطر داخلها.

## Decision

### 1. الشكل النصي وظل السكون

تكون `.viewer-fab` زرًا نصيًا Pill واضحًا، لا دائرة ثابتة:

```css
width: auto;
min-width: var(--pg-touch-target);
min-height: var(--pg-touch-target);
padding: var(--pg-space-2) var(--pg-space-4);
border-radius: var(--pg-radius-control);
font-size: var(--pg-font-size-value);
box-shadow: var(--pg-shadow-panel);
```

ويرث `.viewer-fab-text` حجم الخط، ويبقى في سطر واحد. يُعاد استخدام الرموز القائمة دون تعديل قيمها أو إضافة رموز جديدة.

### 2. التحويم المحروس

توضع حالات التحويم الخاصة بكل من `.viewer-fab` و`.viewer-btn` داخل الحرس الآتي وحده:

```css
@media (hover: hover) and (pointer: fine)
```

لا يُستخدم اكتشاف جهاز أو User-Agent، ولا تُنشأ نقطة كسر عرض لتقرير معنى التفاعل.

تبقى حالة `.viewer-select:hover` القائمة مستقلة؛ فهذا القرار يخص `.viewer-fab` و`.viewer-btn` فقط.

وتبقى حالة الزر المعطّل غير تفاعلية بصريًا، لكن قاعدتها الخاصة بالتحويم تنتقل إلى الحرس نفسه حتى لا يبقى تحويم خاص بـ`.viewer-btn` خارجه.

### 3. حالة الضغط

تحمل `.viewer-fab:active` و`.viewer-btn:active` حالة ضغط داخلية تتبع السابقة القائمة في `.button:active`:

- حد بلون الهوية الداكن القائم.
- `box-shadow` يتضمن `inset`.
- تسطير ذو إزاحة قائمة.
- لا تغيير في الحجم أو الموضع.

### 4. التركيز

يبقى عقد `button:focus-visible` القائم حاكمًا: outline داكن وحلقة ورقية في فجوة الإزاحة. ولأن ظل FAB يُعلن بعد العقد العام في ترتيب CSS، تُضاف له قاعدة `:focus-visible` مركبة تجمع الحلقة الورقية وظل السكون بدل أن يلغي الظل الحلقة في cascade. وتجمع حالة `:active:focus-visible` الحلقة والظل الداخلي معًا. التحويم ليس بديلًا للتركيز.

### 5. الحركة

لا يضيف هذا القرار:

- `transition`.
- `animation`.
- `@keyframes`.
- `transform`.
- Pulse.
- Scale.
- أي رمز مدة زمني جديد.

النبضة أو أي Animation قرار منتج مؤجل، وليست جزءًا من `ADR-0014`.

## Scope

### In Scope

ينحصر التنفيذ في:

1. تحويل `.viewer-fab` من دائرة ثابتة إلى زر نصي Pill واضح مع ظل سكون.
2. حراسة تحويم `.viewer-fab` و`.viewer-btn` بقدرة التحويم الدقيق.
3. إضافة حالة ضغط داخلية للعنصرين.
4. تركيب حلقة focus مع ظل FAB وحالة الضغط دون تعارض cascade.
5. إضافة اختبارات عقد ساكنة للسلوك الجديد.
5. إضافة هذا القرار إلى فهرسي README.
6. تحديث دفتر الأدلة بنتائج التنفيذ الفعلية.

الملفات المسموح تعديلها أو إنشاؤها هي:

```text
assets/css/parmaga.css
tests/test_lesson_ui_contract.py
README.md
docs/ai/ARCHITECT_EVIDENCE_LEDGER.md
docs/decisions/ADR-0014-viewer-control-affordance.md
```

### Out of Scope

خارج النطاق:

- `assets/js/lesson-viewer.js`.
- `index.html` وأي HTML آخر.
- أي SVG أو أصل درس.
- أي سطر داخل `@media print`.
- `@page` و`ADR-0011`.
- البروتوكولات و`PROJECT_VISION.md`.
- القرارات السابقة.
- Dependencies وأدوات البناء وGitHub Actions.
- تغيير أهداف اللمس أو الألوان أو الخطوط أو رموز الهوية.
- إعادة تصميم شامل للعارض.
- Pulse أو Animation أو Transform.
- حذف الفروع أو فتح المرحلة 8.

## Accessibility and Reduced Motion

ظل السكون يضيف دلالة مكانية غير زمنية. وحالة الضغط تستخدم ظلًا داخليًا وتسطيرًا، فلا تعتمد على اللون وحده. والتحويم لا يعمل إلا عندما يعلن الجهاز دعمه للتحويم الدقيق، فلا يُفرض على اللمس أو القلم الخشن.

يبقى `:focus-visible` هو مسار لوحة المفاتيح الحاكم ولا يُستبدل بالتحويم. ولا تتغير أسماء الوصولية أو ترتيب Tab أو أحجام أهداف اللمس.

لأن التنفيذ لا يضيف أي تأثير زمني، فهو متوافق تلقائيًا مع `prefers-reduced-motion`. لا تُضاف كتلة Reduced Motion فارغة أو وهمية لهذا القرار، وتبقى الكتلة القائمة دون تغيير.

## Print Freeze

عقد الطباعة مجمد وفق `ADR-0011`.

- لا يُعدّل أي سطر داخل `@media print`.
- لا تُعدّل `@page`.
- يجب أن تبقى كتلة الطباعة 98 سطرًا.
- يجب أن تبقى بصمتها:
  `f8bf32aa9b06dd8d72704d6abab9a37a987a14c3`.
- يوضع CSS الخاص بهذه المرحلة قبل بداية كتلة الطباعة.

## Consequences and Trade-offs

### Positive

- يصبح الزر العائم مميزًا عن السطح في السكون باستخدام رمز قائم.
- يحصل مستخدم الفأرة أو لوحة اللمس الدقيقة على دلالة تحويم واضحة.
- يحصل الضغط على دلالة داخلية مرئية بلا حركة.
- يبقى التركيز المرئي والوصول بلوحة المفاتيح كما هما.
- لا يُضاف اعتماد أو JavaScript أو HTML.

### Negative

- تختلف دلالة التحويم عمدًا بين الأجهزة الدقيقة وأجهزة اللمس.
- الظل الداخلي أثناء الضغط يحل محل ظل السكون لحظة الضغط، وهو مقصود لتوضيح انغمار العنصر.
- لا يقدم هذا القرار نبضة أو جذب انتباه تلقائي؛ ذلك مؤجل لقرار منتج مستقل إن ثبتت الحاجة إليه.

## Verification

### V1 — تحقق قابل لإعادة التشغيل

يجب أن تثبت الاختبارات والأوامر:

1. `.viewer-fab` زر نصي بعرض تلقائي، وحد أدنى 44px، وحشو واستدارة وحجم خط من الرموز القائمة، وليس دائرة `50%`.
2. ظل سكون `.viewer-fab` يستخدم `var(--pg-shadow-panel)`.
3. تحويم `.viewer-fab` و`.viewer-btn` داخل
   `@media (hover: hover) and (pointer: fine)`.
4. لا تبقى قاعدة تحويم خاصة بهذين العنصرين خارج الحرس.
5. توجد حالة `:active` لكل منهما.
6. حالة الضغط تستخدم `box-shadow` يتضمن `inset`.
7. يبقى عقد `button:focus-visible` قائمًا.
8. لا تحتوي كتلة تنفيذ ADR-0014 على `transform` أو `transition` أو
   `animation` أو `@keyframes`.
9. تبقى بصمة كتلة الطباعة وعدد أسطرها ثابتين.
10. تبقى بصمتا `assets/js/lesson-viewer.js` و`index.html` ثابتتين.
11. تمر مجموعة الاختبارات كاملة بعدد 141 اختبارًا على الأقل.
12. يعطي `verify_lesson.py` النتيجة `RESULT: PASS (0 errors)`.
13. يكون `git diff --check` نظيفًا.
14. ينحصر الفرق في الملفات الخمسة المسموحة.

### V2 — تحقق متصفحي

الفحص المتصفحي الأول موثق بلقطات المالك على Desktop عند `localhost:8000`: أثبت ظهور التنفيذ، لكنه أثبت أيضًا أن الدائرتين ثابتتي 44px والنص 0.75rem لا تعطيان affordance كافيًا، فرفض المالك النتيجة. هذا دليل `Confirmed — visual failure` للتنفيذ الأول، لا نجاحًا بصريًا.

بعد مراجعة Pill يبقى غير مؤكد حتى تُرسل لقطة متصفحية جديدة:

- وضوح هيئة Pill وظل السكون على الحاسب.
- ظهور التحويم على فأرة أو Pointer دقيق.
- عدم تعلق حالة التحويم على الهاتف.
- وضوح حالة الضغط دون قفز أو تغير حجم.
- استمرار وضوح focus المرئي بلوحة المفاتيح.
- الطباعة الفعلية.
- التحقق المرئي مع Reduced Motion.

كل بند غير منفذ من هذه البنود يُسجل `Unknown` أو `Pending`، ولا يرقّى إلى `Confirmed` بناءً على الفحص الساكن.

## Implementation Boundary

لا تعديل JavaScript أو HTML في هذه المرحلة. ولا Commit أو Push أو Pull Request إلا بتفويض صريح لاحق.

يُحفظ CRLF في الملفات القائمة التي تستخدمه. وتُطبّق تعديلات الملفات القائمة عبر FIND/REPLACE حرفي وفريد. ولا تُعاد كتابة اختبار قائم لتسهيل النجاح.

## Rollback

إذا فشل أي عقد قائم، أو تغيرت كتلة الطباعة، أو تغير JavaScript أو HTML، أو تعذر حصر الفرق في الملفات المسموحة، تُستعاد حزمة المرحلة 7.3 كاملة قبل الدمج.

يكون rollback بإزالة قواعد ADR-0014 واختباراتها وفهرستها وقيدها من الدفتر وحذف ملف هذا القرار. ولا يكون rollback بتعديل الاختبارات القديمة أو تحويل نهايات الأسطر أو تعديل عقد الطباعة.
