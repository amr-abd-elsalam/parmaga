# ADR-0002: Design Tokens and Styling Strategy

## Status

Accepted

## Context

يحتوي موقع Parmaga حاليًا على CSS مضمّن داخل `index.html` و`404.html`. توجد قواعد وقيم بصرية مكررة بين الملفين، ولا توجد CSS Custom Properties أو Design Tokens تمثل الألوان والمسافات والخطوط والعناصر المشتركة.

هذا التكرار يجعل الصفحات عرضة للـDrift مع توسع الموقع، وهو خطر مؤكد مع نزول الدروس الأسبوعية بعد 1 سبتمبر 2026 وإضافة صفحات جديدة تحتاج إلى مشاركة الهوية والقواعد الأساسية نفسها.

الموقع ثابت ولا يحتوي على JavaScript أو Dependencies أو Build Step. كما أن الاستضافة المؤقتة على GitHub Pages، مع وجود Cloudflare أمام الموقع، لا تحتاج إلى نظام Styling يتطلب معالجة وقت البناء.

## Decision

- يُستخدم ملف CSS خارجي واحد في المسار `assets/css/parmaga.css`.
- يُقسّم الملف إلى أربع طبقات مرتبة:
  1. Tokens.
  2. Base / Reset.
  3. Components.
  4. Page Scopes.
- تكون كتلة `:root` هي المكان الوحيد المسموح فيه بكتابة قيم الألوان الخام.
- تُحوّل القيم البصرية الحالية إلى Design Tokens مع الحفاظ على الشكل والسلوك الحاليين في Patch A.
- لا يُنشأ Token لمدة انتقال في Patch A، لأن CSS الحالي لا يحتوي على قيمة انتقال يمكن استخراجها دون اختراع قيمة جديدة.
- يُعرّف Parmaga Memo Palette في ملف الـTokens الآن، لكنه لا يُطبّق في Patch A.
- ملف الـTokens داخل الـRepository هو مصدر الحقيقة للألوان، وتُنتج المذكرات منه. اتجاه الحقيقة الحاكم هو:

```text
Repo → المذكرة
```

وليس العكس.

- يُعتمد الاتجاه A للهوية: تتبع هوية الموقع هوية المذكرة الكريمية والخشبية والكحلية، لكن تطبيق هذه الهوية مؤجل إلى Patch B.
- يسجل تقييم التباين النتائج التالية:
  - الكحلي `#1B4C7E` على الورق `#FDFBF2` يحقق تقريبًا `8.5:1`.
  - الأورنج `#E07B2A` على الورق يحقق تقريبًا `2.9:1` ويفشل للاستخدام كنص.
  - الذهبي `#C9A227` على الورق يحقق تقريبًا `2.3:1` ويفشل للاستخدام كنص أو حد يحتاج إلى تباين كافٍ، لكنه صالح للاستخدام فوق الأسطح الكحلية.
- يُستخدم `--pg-orange-text` بدل `--pg-orange-500` عندما تكون الحاجة إلى نص أورنج متباين.
- لا يُنفذ Patch B ضمن هذا القرار التنفيذي.
- حُسم شرط معاملة صورة الإعلان الخاص بـPatch B على النحو التالي: يبقى الأصل الحالي دون تعديل، ودون استبدال أو إعادة تصدير، ودون دمج Texture أو Frame داخل الصورة. يُطبّق السياق الورقي والخشبي عبر HTML وCSS المحيطين بالصورة فقط، ودون أي External Production assets.
- شكل الدروس، سواء كان صورًا نقطية أو HTML/SVG، قرار مفتوح مؤجل وغير محسوم. يجب حسمه قبل 1 سبتمبر 2026، وهو خارج نطاق هذا الـADR.

رُفضت البدائل التالية:

- الإبقاء على CSS مضمّنًا داخل كل ملف HTML.
- تكرار Design Tokens مضمّنة داخل كل صفحة.
- تقسيم CSS إلى Critical CSS مضمّن وملف خارجي منفصل.
- إدخال Tailwind أو Sass أو أي Dependency أو Build Step.

## Consequences

- تضيف الزيارة الأولى طلب شبكة واحدًا لتحميل ملف CSS.
- يسمح الملف الخارجي للمتصفح وCloudflare بتخزين CSS مؤقتًا ومشاركته بين كل الصفحات الحالية والقادمة.
- يقل تكرار القواعد والقيم البصرية، ويصبح تعديل الهوية مستقبلًا أكثر اتساقًا وأقل عرضة للـDrift.
- يبقى الموقع HTML/CSS ثابتًا، دون JavaScript أو Dependencies أو Build Step.
- لا يتعارض هذا القرار مع `ADR-0001`.
- لا يحتاج القرار إلى Rewrites أو Custom Headers أو Migration.
- لا توجد قاعدة بيانات أو حالة محفوظة مرتبطة بالتغيير.
- يمكن التراجع عن Patch A بتراجع Git واحد يعيد كتل CSS المضمّنة ويحذف الملفين الجديدين.
- تبقى هوية المذكرة معرفة فقط وغير مطبقة حتى اعتماد Patch B وتنفيذه.
