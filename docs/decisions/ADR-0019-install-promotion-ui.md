# ADR-0019: Install Promotion UI — نطاق المرحلة وحدودها

## Status

Accepted

## Context

هذا قرار توثيقي بحت. لا يتضمن تنفيذًا، ولا يُنشئ ولا يعدّل أي HTML أو CSS أو JavaScript أو manifest أو أيقونة. تنفيذ ما يقرره يحتاج baseline جديدًا وإذن مالك مستقلًا وPR منفصلًا. ويُقرأ مع ADR-0007 (عقد ملف الأنماط المشترك، صفر dependencies، صفر build step) ومع ADR-0018 (`display: minimal-ui`، و§11 تأجيل Service Worker والتخزين المؤقت إلى قرار وPR مستقلين)، ولا ينسخ أيًّا منهما ولا ينقضهما، ولا يُلغي أي قرار سابق.

### 1. الحالة القائمة

الموقع static خام: بلا `package.json`، وبلا build step، وبلا dependencies، وبلا submodules، ينشر عبر GitHub Pages من `main` ومن الجذر (`Confirmed` — أدلة محلية مسلّمة من المالك، حزم A–I وM1–M5).

ثلاث صفحات HTML فقط، كلها ترتبط بـ`/manifest.webmanifest` وبـ`/assets/css/parmaga.css`: `index.html`، و`404.html`، وصفحة الدرس `courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/index.html` (`Confirmed` — المصدر نفسه).

الموقع installable من ناحية البنية التحتية: manifest صالح ومجموعة أيقونات معتمدة بموجب ADR-0018 (`Confirmed`). لكن لا توجد أي واجهة تدعو المستخدم إلى التثبيت أو ترشده إليه (`Confirmed`). وiOS لا يتيح تثبيتًا برمجيًا من الصفحة؛ الإضافة إلى الشاشة الرئيسية إجراء يدوي يبدأه المستخدم من واجهة المتصفح (`Reported` — WebKit، "WebKit Features in Safari 17.0"، https://webkit.org/blog/14445/webkit-features-in-safari-17-0/).

يترتب على ذلك تأطير المشكلة: المطلوب طبقة **ترويج** (Promotion) لا طبقة **قدرة** (Capability). القدرة موجودة بالفعل حيث تدعمها المنصة، والناقص هو دعوة مرئية ومحترمة تستثمرها.

### 2. ما لا يقرره هذا القرار

Service Worker والتخزين المؤقت والعمل دون اتصال كلها خارج هذه المرحلة، تنفيذًا لا ذكرًا. ADR-0018 §11 يؤجلها ويشترط لها ADR وPR مستقلين، وهذا القرار لا ينقض ذلك ولا يستبقه. ذكر Service Worker هنا توثيقي بحت لتسجيل استبعاده وربط الاستبعاد بمصدره.

### 3. أدلة الطبقة الهندسية القائمة (M1)

`.page-lesson .lesson-viewer-controls:not([hidden])` عنصر `fixed`، إزاحته الجانبية من `--pg-float-inset`، وإزاحته السفلية تشمل `env(safe-area-inset-bottom)`، وطبقته `z-index: 30` (`Confirmed` — مخرج قراءة محلي مسلّم من المالك). اللوحة المفتوحة تبلغ `50vh`/`50dvh` على الهاتف، وتصل إلى `60vh`/`60dvh` عند `800px` فما فوق، حيث تنتقل الأدوات إلى `inset-inline-end` (`Confirmed`). و`main` يحجز 120px أسفل الهاتف و140px على الشاشات الأوسع (`Confirmed`). وكتلة الطباعة القائمة تخفي `lesson-viewer-controls` (`Confirmed`).

### 4. أدلة DOM المقيسة على صفحة الدرس

مخرج المحلل القرائي المسلّم من المالك (`Confirmed` — owner-supplied local command output):

```
MATCHES=1
MATCH_1_LINE=36
MATCH_1_ANCESTORS=html > body > main
MATCH_1_DATA_PANEL_OPEN=<absent>
MATCH_1_DIRECT_BODY_CHILD=false
```

ومواضع أخرى مقيسة على الملف نفسه: `26:<script src="/assets/js/lesson-viewer.js" defer></script>`، و`28:<body class="page-lesson">`، و`29:<main>`، و`36:<div class="lesson-viewer-controls" data-viewer-controls hidden>`، و`589:</main>`، و`590:</body>` (`Confirmed`).

والسمة `data-panel-open` غائبة عن HTML الابتدائي لكنها تُدار من مصدر الحالة نفسه في `assets/js/lesson-viewer.js`: `setAttribute('data-panel-open', state.openPanel)` عند السطر 990، و`removeAttribute('data-panel-open')` عند السطر 992 (`Confirmed`). كما يُدرج العارض عناصر شقيقة لأدوات التحكم تحت الأب نفسه: `insertBefore(stage, controls.nextSibling)` عند السطر 1504، و`insertBefore(notice, stage)` عند السطر 1511 (`Confirmed`).

### 5. الرموز المتاحة والناقصة (M2)

متاح: `--pg-radius-control`، `--pg-focus-width`، `--pg-focus-offset`، `--pg-touch-target`، `--pg-float-gap`، `--pg-float-inset`، `--pg-shadow-panel`، ورموز spacing وcolor ومنها `--pg-wood-700` و`--pg-paper` (`Confirmed`). غير متاح: أي token لـ`z-index`، وأي token للحركة أو المدة أو منحنى التسارع (`Confirmed`).

### 6. خط الأساس المتصفحي (M4)

لا baseline موثق لدعم `<dialog>` أو `showModal()` في هذا المشروع (`Confirmed`). و`tools/browser_baseline.py` يبحث عن Chrome أو Chromium أو Edge فقط، ولا يثبّت Safari ولا Firefox، ولا يختبر `dialog` ولا `beforeinstallprompt` (`Confirmed`). لذلك لا يجوز الاستشهاد به دليلًا على أي منهما.

### 7. المصادر الخارجية

Chrome Developers، "Revisiting Chrome's installability criteria" — https://developer.chrome.com/blog/update-install-criteria. يعالج المصدر معايير قابلية التثبيت في Chrome وتغيّرها (`Reported`). يُنقل مضمونه وصفًا فقط، ويُحظر اشتقاق **توقّع** لنتيجة بوابة G1 منه.

WebKit، "WebKit Features in Safari 17.0" — https://webkit.org/blog/14445/webkit-features-in-safari-17-0/. يربط المصدر سلوك تطبيق الشاشة الرئيسية بوضع العرض `standalone` أو `fullscreen` (`Reported`). أثر ذلك على `minimal-ui` **`Unknown`** ولا يُرقّى إلى `Confirmed` بالاستدلال. ويشير المصدر نفسه إلى أن Safari View Controller يدعم الإضافة إلى الشاشة الرئيسية وأن متصفحات أخرى يمكنها تنفيذها (`Reported`)؛ فيُحظر في هذا القرار وفي أي تنفيذ مشتق منه أي عبارة تفيد أن webviews أو متصفحات iOS الأخرى تفتقر إلى هذه القدرة.

## Decision

### D1 — نطاق المرحلة وحدودها

تُعتمد مرحلة Install Promotion UI بالحدود التالية (`Decision`): صفر Service Worker، وصفر تخزين مؤقت أو Cache API، وصفر صفحة offline، وصفر تعديل على `manifest.webmanifest` أو على قيمة `display` المعتمدة `minimal-ui`، وصفر framework أو مكتبة أو أداة أو dependency جديدة.

وبصمة التنفيذ اللاحقة محصورة حصرًا في ثلاثة أشياء (`Requirement`): إضافة ملف JavaScript واحد هو `assets/js/pwa-install.js`؛ وإضافة قسم مكوّن معزول واحد في `assets/css/parmaga.css` محصور بعلامتي تعليق بداية ونهاية دون تعديل أي قاعدة قائمة؛ وسطر `<script defer>` واحد لكل صفحة من الصفحات الثلاث. أي حاجة تتجاوز هذه البصمة توقف التنفيذ وتستدعي قرارًا جديدًا، ولا تُعالج باجتهاد داخل PR التنفيذ.

### D2 — الطبيعة الحوكمية للإذن

هذا القرار إذن مبدئي للتنفيذ اللاحق فقط، ولا يجيز بذاته كتابة سطر واحد من كود المنتج (`Decision`). PR التنفيذ يحتاج baseline جديدًا مقيسًا وإذن مالك مستقلًا. وتُسجَّل للملفات المجمّدة بصمات جديدة بالطريقة المعتمدة في المشروع كما هي مثبتة في `docs/ai/ARCHITECT_EVIDENCE_LEDGER.md`، ولا تُخترع صيغة بصمة جديدة (`Requirement`).

### D3 — ملف الأنماط المشترك والاستثناء الوحيد المطلوب

`assets/css/parmaga.css` هو ملف CSS المشترك الوحيد، وإنشاء ملف CSS ثانٍ مرفوض بموجب ADR-0007 (`Confirmed` — قراءة ADR-0007 المسلّمة من المالك). يُحظر إنشاء `assets/css/pwa-install.css` أو أي بديل عنه (`Decision`).

الاستثناء الوحيد الذي يوصّفه هذا القرار هو: **إذن محدود وقابل للسحب** بتعديل `assets/css/parmaga.css` عبر إضافة قسم مكوّن معزول واحد محصور بعلامتي تعليق، دون تعديل أي قاعدة قائمة ودون إعادة ترتيب أو إعادة تنسيق ما قبله وما بعده (`Decision`). سحب الإذن يعني حذف القسم بين العلامتين، وهو ما يجعل التراجع ميكانيكيًا لا اجتهاديًا.

### D4 — الاعتماد على `<dialog>` وسلوك غيابه

عند غياب `HTMLDialogElement` أو غياب `showModal()` في بيئة التشغيل، يصمت مسار iOS تمامًا (`Decision`): لا يُعرض زر ميت، ولا يُكتب focus trap يدوي بديل، ولا يُستبدل العنصر بـ`div` يحاكي الحوار. ولا يتأثر فرع Chromium بهذا الغياب، لأنه لا يحتاج النافذة أصلًا (`Requirement`).

### D5 — بوابة G1

انظر البند 12 أدناه. النتيجة `Unknown` في تاريخ هذا القرار، والمكتوب هنا هو **إجراء الحكم لا الحكم**.

### D6 — القيد الموروث على iOS

عدم ضمان كشف حالة «مثبّت مسبقًا» على iOS في ظل `display: minimal-ui` يُقبل قيدًا موثقًا، لا سببًا لكسر ADR-0018 ولا لتغيير قيمة `display` (`Decision`). ويُحظر في هذا القرار وفي أي تنفيذ مشتق منه أي ادعاء عن سلوك ما بعد التثبيت على iOS بلا اختبار جهاز حقيقي (`Requirement`).

### D7 — قرار الموضع والفصل الهندسي

انظر القسم «الموضع والفصل الهندسي» أدناه، وهو جزء لا يتجزأ من هذا القرار.

### 1. آلة الحالة

الحالة الافتراضية **صامتة** (`Decision`). لا يُدرَج أي عنصر في DOM ولا تُعرض أي واجهة إلا بالدخول في إحدى حالتين: `prompt-ready` على Chromium بعد وصول حدث `beforeinstallprompt` فعليًا، أو `ios-manual` ضمن النطاق المحدد في البند 3 أدناه.

والحالات `hidden-app-mode` (التطبيق يعمل في وضع مثبّت) و`suppressed` (بعد `dismissed` في الجلسة نفسها) و`unsupported` كلها صامتة بلا أي عنصر في DOM، لا مخفيًا ولا معطّلًا (`Requirement`).

### 2. كشف وضع التطبيق

لأن الوضع المعتمد في هذا المشروع `minimal-ui`، فإن فحص `standalone` وحده غير كافٍ ويعطي نتيجة خاطئة (`Decision`). المطلوب مطابقة أي من `standalone` أو `minimal-ui` أو `fullscreen`، أو كون `navigator.standalone` صحيحًا، مع فحص تأكيدي لعدم مطابقة `(display-mode: browser)` يُتجاهل بأمان عند غياب دعمه، ومستمعات `change` تُخفي الواجهة عند تغيّر الوضع أثناء الجلسة (`Requirement`).

### 3. فرع Chromium

المطلوب سلوكيًا (`Requirement`): منع الواجهة التلقائية للمتصفح وحفظ مرجع الحدث، ثم كشف واجهة الترويج بعد ذلك فقط؛ وتشغيل `prompt()` الرسمي عند نقر المستخدم وبتفاعله المباشر لا تلقائيًا؛ ومسح المرجع فور استخدامه لأنه صالح لمرة واحدة؛ والإخفاء في نتيجتي `accepted` و`dismissed` كلتيهما؛ وراية جلسة تُصمِت أي حدث لاحق في الجلسة نفسها بعد `dismissed`؛ والإخفاء والتنظيف الكامل عند `appinstalled`. ويُحظر فتح أي prompt تلقائيًا في أي مسار (`Decision`).

ويجب أن يعالج التنفيذ ثلاث حالات فشل معالجة آمنة صريحة (`Requirement`): إذا رمى `prompt()` استثناءً؛ وإذا رُفض `userChoice` برفض (rejection) بدل الاستقرار؛ وإذا تعذّر `sessionStorage` أو رمى في التصفح الخاص. وفي كل حالة فشل تُطبَّق النتيجة نفسها: صفر خطأ في Console، وإخفاء حتمي للزر، وعدم إعادة عرض تلقائي.

### 4. فرع iOS

النطاق في المرحلة الأولى هو **Safari على iOS و iPadOS فقط** (`Decision`)، اتساقًا مع النص المعتمد الذي يذكر زر المشاركة في Safari بالاسم.

كشف Safari يعتمد heuristic تجمع إشارات المنصة مع `maxTouchPoints` لمعالجة iPad الذي يعرّف نفسه `MacIntel`، ومع وجود خاصية `navigator.standalone`؛ وهذه heuristic **ليست** API معيارية مضمونة (`Decision`). وتبقى false positives و false negatives **`Unknown`** حتى اختبار أجهزة حقيقية.

والسلوك في متصفحات iOS الأخرى وفي webviews هو **الصمت كافتراض محافظ ضمن هذه المرحلة** (`Decision`)، وهو اختيار نطاق لا ادعاء قدرة؛ وWebKit يذكر أن Safari View Controller يدعم الإضافة إلى الشاشة الرئيسية وأن متصفحات أخرى يمكنها تنفيذها (`Reported`). ويُحظر مطلقًا أي ادعاء بتثبيت برمجي على iOS (`Requirement`).

### 5. النافذة الإرشادية

`<dialog>` أصلي يُفتح بـ`showModal()`، مع `aria-modal="true"` و`aria-labelledby` مربوط بمعرّف العنوان، ودعم Escape عبر حدث `cancel`، وزر إغلاق مرئي وواضح، وإعادة تركيز صريحة إلى زر التثبيت عند `close`، وحصر تركيز مستمد من المواصفة لا مكتوب يدويًا، وخطوات مرقّمة بعناصر قائمة دلالية، ورموز SVG مضمّنة موسومة `aria-hidden` وبلا Emoji (`Requirement`).

ولأن `showModal()` يضع العنصر في **top layer**، لا يُخصص للنافذة أي `z-index` ولا تدخل في منافسة الطبقات مع أدوات الدرس (`Decision`).

والإغلاق بالنقر خارج اللوحة يعتمد **wrapper داخليًا** أو اختبار حدود اللوحة (`Decision`)، لأن مقارنة `event.target` بعنصر الـdialog وحده قد تحسب النقر على مساحة فارغة **داخل** الـdialog نقرًا خارجيًا بحسب بنية العنصر.

وقفل التمرير يكون عبر class على `<html>` مع حفظ موضع التمرير واستعادته، ويُتجنّب أسلوب `position: fixed` على `body` (`Decision`).

### 6. التصميم والرموز

`<button>` حقيقي لا عنصر يحاكي زرًا؛ وهدف لمس مبني على `--pg-touch-target` بما لا يقل عن 44×44؛ وحلقة تركيز عبر `--pg-focus-width` و`--pg-focus-offset`؛ ونصف قطر من `--pg-radius-control`؛ وظل من `--pg-shadow-panel`؛ وخصائص منطقية `inset-inline-*` و`inset-block-*` لأن الموقع RTL؛ وصفر ألوان خام إذ يشير كل لون إلى token قائم (`Requirement`).

ولأن المشروع لا يملك token للحركة، يُجيز هذا القرار تعريف خاصية مخصّصة محلية واحدة للمدة **داخل القسم المعزول فقط** بسابقة `--pg-install-` (`Decision`)، ويُسجَّل غياب الـtoken العام دينًا تقنيًا يُعالج في قرار رموز مستقل. وهذا **لا يوصف** بأنه استثناء من ADR-0007؛ الاستثناء الوحيد الموصوف هو ما ورد في D3.

### 7. الحركة المخفّضة

`@media (prefers-reduced-motion: reduce)` يُلغي الحركة إلغاءً لا يبطئها (`Requirement`).

### 8. صفر Layout Shift

العنصر `fixed`، ويُبنى من JavaScript بعد الرسم الأول، ولا يوجد له markup في أي صفحة من الصفحات الثلاث (`Decision`). فلا وميض قبل اكتمال التحقق، ولا زر ميت عند تعطّل JavaScript أو حجبه.

### 9. صفر تتبع

لا telemetry ولا analytics ولا أي طلب شبكة ينشئه المكوّن، ولا أي تفاعل مع `beacon.min.js` الذي يحقنه Cloudflare (`Decision`).

### 10. نصوص الواجهة المعتمدة

تُدرج كما هي (`Decision`): زر الواجهة «ثبّت برمجة»؛ عنوان الإرشادات «إضافة برمجة إلى الشاشة الرئيسية»؛ الخطوات بالترتيب «اضغط زر المشاركة في Safari.» ثم «اختر “إضافة إلى الشاشة الرئيسية”.» ثم «اضغط “إضافة” للتأكيد.»؛ وزر الإغلاق «إغلاق».

يجوز تحسين الصياغة بشرطين: ألا يتغير المعنى، وألا توحي الصياغة الجديدة بتثبيت برمجي على iOS.

### 11. الموضع والفصل الهندسي (D7)

**المبدأ الحاكم:** `z-index` لا يحل تعارضًا هندسيًا (`Decision`). خفض الطبقة قد يجعل الزر مغطى وغير قابل للنقر، وoffset ثابت لا يغطي لوحة قد تبلغ `50dvh` أو `60dvh`. الحل هو الفصل الهندسي، والطبقة حماية إضافية لا أكثر.

**11.1 الطبقة.** طبقة زر الترويج أدنى من 30، أي أدنى من طبقة أدوات الدرس (`Requirement`). والنافذة في top layer بلا `z-index` وفق البند 5.

**11.2 الصفحات بلا عارض دروس** (`index.html` و`404.html`): `inset-inline-end` من `--pg-float-inset`، والإزاحة السفلية من `--pg-float-gap` مضافًا إليها `env(safe-area-inset-bottom)` (`Requirement`).

**11.3 صفحة الدرس.** يستقر الزر فوق المساحة المحجوزة أصلًا في `main` — 120px دون `800px`، و140px عند `800px` وما فوق — بمرآة نقطة الانكسار نفسها، عبر خاصية مخصّصة تُعرّف داخل القسم المعزول وحده (`Requirement`).

**11.4 قاعدة الشقيق العام — معتمدة بشروط تنفيذ ملزمة.** القاعدة الأساسية CSS خالص بلا مراقبة JavaScript: يُخفى جذر المكوّن عبر محدد شقيق عام يعتمد وجود `[data-panel-open]` على `.lesson-viewer-controls` (`Decision`).

سند الاعتماد من الأدلة المقيسة: العنصر موجود مرة واحدة فقط في الصفحة (`Confirmed`)؛ والسمة `data-panel-open` تُدار من مصدر الحالة نفسه في العارض عند السطرين 990 و992 وتُعد سلوكًا مستقرًا (`Confirmed`)؛ وإدراج أشقاء تحت الأب نفسه عرف قائم في العارض عند السطرين 1504 و1511 (`Confirmed`).

وانحراف موثق عن الصياغة الحرفية لشرط «ابن مباشر لـ`body`»: الدليل يثبت أن الأسلاف `html > body > main` وأن `MATCH_1_DIRECT_BODY_CHILD=false` (`Confirmed`). الشرط بصياغته الحرفية **غير مستوفى**، ولا يُدّعى استيفاؤه. المعتمد هو الجوهر التقني للشرط: محدد الشقيق العام يعمل بين شقيقين تحت أب مشترك أيًّا كان الأب، والمطلوب تحقق الأب المشترك وترتيب الجذر بعد أدوات التحكم. وقد قرر المالك صراحةً اعتماد القاعدة على هذا الأساس.

ويترتب على ذلك عقد تنفيذ ملزم لملف `assets/js/pwa-install.js` (`Requirement`): على صفحة الدرس يُنشأ جذر المكوّن **داخل `main`**، ويوضع **بعد** `.lesson-viewer-controls` في ترتيب الأشقاء، بحيث يكون الاثنان شقيقين تحت الأب نفسه؛ وعلى الصفحتين الأخريين يُنشأ الجذر آخر أبناء `body`. ويُحظر تعديل `lesson-viewer.js` لإتاحة أي من ذلك.

**11.5 متطلب تحقق سابق لتثبيت المحدد.** لأن الجذر ينتقل من مستوى `body` إلى داخل `main`، يجب على PR التنفيذ أن يثبت أولًا أن لا `transform` ولا `filter` ولا `perspective` ولا `contain: paint` ولا `will-change` على `main` أو على أي حاوٍ بينه وبين الجذر (`Requirement`)، لأن أيًّا منها يحوّل الكتلة الحاوية لعنصر `fixed` من إطار العرض إلى ذلك العنصر ويكسر التموضع. حالة هذا الفحص **`Unknown`** في تاريخ هذا القرار إذ لم يُقس. إن ثبت وجود أي منها، يسقط الإدراج داخل `main` ويُفعَّل `F1`.

**11.6 `F1` — fallback ملزم.** إذا تعذّر وقت التنفيذ إثبات وجود `.lesson-viewer-controls` مرة واحدة، أو تعذّر إدراج جذر المكوّن بعده وتحت الأب نفسه، أو سقط فحص البند 11.5: **لا تُعرض واجهة Install Promotion على صفحة الدرس في المرحلة الأولى**، ويبقى السكربت محمّلًا وصامتًا هناك، مع شرط إعادة نظر معلن (`Decision`). ويُحظر تجاوز الفشل بمراقبة DOM أو بمحدد تقريبي أو بأي تعديل على `lesson-viewer.js`.

**11.7 محظورات دائمة في هذه المرحلة.** لا تعديل على `assets/js/lesson-viewer.js`، ولا `MutationObserver` على أدوات الدرس؛ ولا يُمنح هذا الإذن في المرحلة الأولى (`Decision`).

**11.8 الطباعة.** يُخفى المكوّن عند الطباعة بقاعدة داخل القسم المعزول، دون تعديل كتلة الطباعة القائمة (`Requirement`).

**11.9 عتبات التحقق التي يقيسها PR التنفيذ** (`Requirement`): عرض 320px، ومقاس 360×640، وارتفاع قصير قرابة 500px، وعلى جانبي نقطة الانكسار `800px`، وفي حالتي اللوحة مغلقة ومفتوحة، وعلى جهاز به notch. ومعيار عدم التقاطع مركّب: عدم التغطية البصرية **و**عدم اعتراض النقر معًا؛ استيفاء أحدهما دون الآخر فشل.

### 12. بوابة G1 (D5)

G1 إجراء واجب سابق لقبول معيار Chromium (`Decision`): التحقق تجريبيًا مما إذا كان Chrome يطلق `beforeinstallprompt` في بيئة النشر الحالية دون Service Worker. تُسجَّل نتيجتها لاحقًا `Confirmed` إيجابًا أو سلبًا، بمخرج ملصق.

**لا يتضمن هذا القرار أي توقّع لنتيجة G1 ولا ترجيحًا لأحد الاحتمالين. النتيجة `Unknown`، والمكتوب هنا إجراء الحكم لا الحكم.**

وإذا لم يطلق Chrome الحدث دون Service Worker: لا يُضاف Service Worker للتحايل على المعيار؛ ولا يوصف معيار Chromium بأنه Passed؛ وتُقبل المرحلة iOS-functional مع فرع Chromium كامن وصحيح شرطيًا، بتوثيق واضح وقبول صريح من المالك؛ ويبقى التثبيت من قائمة المتصفح قدرة قائمة خارج واجهة المكوّن؛ وأي حل لاحق يحتاج القرار المستقل الذي يشترطه ADR-0018 §11 (`Decision`).

ولا يُستشهد بـ`tools/browser_baseline.py` دليلًا على `beforeinstallprompt` ولا على `dialog`، لأنه لا يختبر أيًّا منهما (`Confirmed`).

### 13. البدائل المرفوضة

زر دائم الظهور: مرفوض لأنه يعرض دعوة لا معنى لها في السياقات التي لا تدعمها أو حيث التطبيق مثبّت أصلًا، ويستهلك مساحة على الشاشة دائمًا مقابل فائدة عرضية.

markup مسبق في الصفحات: مرفوض لأنه يُدخل وميضًا قبل اكتمال التحقق، ويترك زرًا ميتًا عند تعطّل JavaScript، ويكسر شرط صفر Layout Shift، ويوزّع الميزة على ثلاثة ملفات HTML بدل ملف واحد.

ملف CSS ثانٍ: مرفوض بموجب D3 وبموجب عقد ملف الأنماط المشترك في ADR-0007.

`div` بدلالات dialog مع focus trap يدوي: مرفوض لأنه يعيد بناء سلوك تقدّمه المواصفة (top layer، وinert للخلفية، وحصر التركيز، وEscape)، ويُنتج أخطاء وصولية يصعب اختبارها، مقابل مكسب لا يذكر.

إضافة Service Worker لإرضاء خوارزمية Chrome: مرفوض لثلاثة أسباب مجتمعة: أنه ينقض ADR-0018 §11 الذي يشترط قرارًا وPR مستقلين؛ وأنه يقلب طبقة ترويج إلى طبقة بنية تحتية بحدود مخاطر مختلفة تمامًا؛ وأن معايير قابلية التثبيت في Chrome موضوع مراجعة متغيّر بحسب المصدر الأول (`Reported` — Chrome Developers، https://developer.chrome.com/blog/update-install-criteria)، ويُنقل هذا وصفًا لا تنبؤًا بنتيجة G1.

### 14. التراجع

التراجع الكامل ثلاث خطوات ميكانيكية (`Decision`): حذف ملف JavaScript واحد؛ وحذف القسم المعزول من `assets/css/parmaga.css` بين علامتي التعليق؛ وحذف ثلاثة أسطر `<script>`. لا هجرة بيانات، ولا أثر باقٍ، ولا اعتماد عكسي من أي ملف آخر.

## Consequences

### إيجابية

يصبح للموقع مسار ترويج تثبيت محدد المعالم دون أي تكلفة بنية تحتية: صفر dependency، وصفر طلب CSS إضافي، وملف JavaScript واحد مؤجّل، وصفر Layout Shift، وصفر telemetry. وتُحفظ حدود ADR-0018 §11 كاملة، فلا يتسلل Service Worker من باب جانبي. ويحصل PR التنفيذ على عقد مكتوب — نصوص، وحالات، وموضع، وعتبات قياس — يغنيه عن الاجتهاد المعماري.

### سلبية ومقبولة

نطاق المرحلة الأولى أضيق من الممكن تقنيًا: متصفحات iOS الأخرى وwebviews خارج التغطية، وهو اختيار محافظ لا حكم على قدرتها. وفرع Chromium يبقى معلقًا على نتيجة G1 غير المعروفة. وكشف Safari يظل heuristic لا API. وقد تصمت الواجهة على صفحة الدرس كليًا إن فُعِّل `F1`.

### حدود باقية

`beforeinstallprompt` دون Service Worker: **`Unknown`** حتى تنفيذ G1، وبلا أي توقّع لنتيجتها.

كشف حالة «مثبّت» على iOS مع `minimal-ui`: قيد موروث موثق (D6)، وسلوك ما بعد التثبيت على iOS **`Unknown`** حتى اختبار جهاز حقيقي.

false positives و false negatives في heuristic كشف Safari: **`Unknown`** حتى اختبار أجهزة حقيقية.

دعم `<dialog>` و`showModal()` في المتصفحات المستهدفة: **`Unknown`**، إذ لا baseline موثق، والأداة القائمة لا تختبره.

الكتلة الحاوية لعنصر `fixed` داخل `main` على صفحة الدرس: **`Unknown`** حتى فحص البند 11.5.

التداخل البصري الفعلي على الأجهزة: **`Unknown`** حتى قياس العتبات في البند 11.9.

هذه كلها حدود متصفح وحوكمة وقياس، لا عيوب تنفيذ.

### متابعات مطلوبة

تنفيذ G1 وتسجيل نتيجتها بمخرج ملصق. وقرار رموز يعالج غياب token الحركة وغياب token الـ`z-index`. وتوسيع `tools/browser_baseline.py` ليغطي ما لا يغطيه اليوم، بقرار مستقل. وأي عمل على Service Worker أو التخزين المؤقت يبقى محكومًا بـADR-0018 §11.
