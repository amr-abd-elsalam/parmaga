# ADR-0004: المعرّفات التقنية والمسارات الدائمة للمحتوى التعليمي

## Status

Accepted

## Context

اعتمد `ADR-0003` التسلسل البنيوي التالي للمحتوى التعليمي:

```text
Course → Term → Chapter → Lesson
```

واعتمد أن الدرس هو أصغر وحدة لها URL مستقل، وأن صفحات الدرس والمفاهيم داخله تُعنون بمراسي ثابتة داخل مستند الدرس نفسه. كما اعتمد شجرة مجلدات ثابتة يكون في كل مستوى منشور منها ملف `index.html` فعلي، دون Router أو JavaScript أو Build Step أو SPA fallback:

```text
courses/
    index.html
    <course>/
        index.html
        <term>/
            index.html
            <chapter>/
                index.html
                <lesson>/
                    index.html
```

وأجّل `ADR-0003` اختيار المعرّفات التقنية الفعلية للمراحل والترمات والفصول والدروس حتى اعتماد أول محتوى حقيقي.

المحتوى الحالي يخص مادة البرمجة والذكاء الاصطناعي، ويستهدف مرحلتين معتمدتي العرض:

- أولى بكالوريا.
- ثانية بكالوريا.

ولكل مرحلة ترمان:

- ترم أول.
- ترم ثاني.

عدد الفصول داخل الترم وعدد الدروس داخل الفصل متغيران، ولا يجوز تثبيتهما معماريًا.

تفتح رؤية المشروع الباب لإضافة مواد دراسية وأنظمة تعليمية أخرى مستقبلًا. إذا مثّل معرّف `Course` المرحلة وحدها، فقد يؤدي إدخال مادة ثانية داخل المرحلة نفسها إلى تصادم في المسارات أو إلى الحاجة لإضافة مستوى جديد يكسر جميع الروابط المنشورة. وفي المقابل، فإن إضافة مستوى مستقل للمادة الآن ستغيّر التسلسل الذي اعتمده `ADR-0003` وتضيف فهارس ومجلدات يدوية جديدة.

المشروع موقع ثابت مستضاف مؤقتًا على GitHub Pages مع Cloudflare أمامه. لا يوجد Router أو Rewrites داخل المستودع، والمسارات غير الموجودة تعيد HTTP 404 حقيقيًا. لذلك تصبح أسماء المجلدات المنشورة جزءًا دائمًا من العقد العام للموقع، ولا يمكن التعامل معها بوصفها تفاصيل تنفيذية قابلة للتغيير لاحقًا.

يجب أن تعمل الروابط عند نسخها ومشاركتها من الهواتف، بما في ذلك واتساب وتيليجرام، دون الاعتماد على كيفية عرض تطبيق بعينه للأحرف غير اللاتينية. الأحرف العربية في URLs قابلة للاستخدام والفهرسة، لكنها قد تظهر عند النسخ أو المعالجة في صورة percent-encoded طويلة. أما النقل الصوتي إلى الحروف اللاتينية فلا يملك معيارًا واحدًا ثابتًا، وقد ينتج تهجئات متعددة للمعنى نفسه.

يعتمد `ADR-0003` كذلك أن أسماء العرض منفصلة عن المعرّفات التقنية، وأن المعرّفات تكون ثابتة وآمنة للمسارات ولا تحمل مسافات أو محارف تحتاج إلى ترميز في الروابط.

يجب أن تكون تسمية أصول SVG مشتقة مباشرة من مسار الدرس، لأن صاحب المشروع سيرفع مئات الملفات يدويًا بعد Sessions أوفلاين متكررة. لا يجوز أن يتطلب نظام التسمية تعديل المحتوى الداخلي لملفات SVG أو نقل النصوص منها أو إعادة توليدها.

## Decision

### 1. مجموعة المحارف وقواعد كتابة المعرّفات

تكون جميع معرّفات المسارات وأسماء ملفات الأصول:

- مكتوبة بأحرف ASCII.
- مكتوبة بالحروف الإنجليزية الصغيرة lowercase.
- مكوّنة من الأحرف `a-z` والأرقام `0-9` والشرطة `-` فقط.
- خالية من المسافات والشرطة السفلية `_`.
- خالية من الأحرف العربية والأحرف ذات العلامات أو التشكيل.
- خالية من Query Parameters بوصفها جزءًا من هوية المحتوى.
- غير حساسة للغة العرض أو لتغيير العنوان المرئي.

تُستخدم الإنجليزية الدلالية، ولا تُستخدم العربية أو الكتابة العربية المنقولة صوتيًا أو المعرّفات الرقمية الغامضة للمستويات العليا.

تكون جميع أسماء المجلدات والملفات lowercase. ويُكتب ملف الدخول إلى كل مجلد منشور باسم:

```text
index.html
```

بهذه الحالة الحرفية، لأن GitHub Pages حساس لحالة الأحرف.

### 2. تعريف Course

يُعدّل هذا القرار الوصف الحالي لـ`Course` في `ADR-0003` تعديلًا محدودًا.

بدلًا من أن تمثل هوية `Course` المرحلة الدراسية وحدها، تصبح الهوية التقنية للـ`Course` ممثلة لتقديم تعليمي يجمع:

```text
Subject × Educational Stage
```

أي:

```text
المادة × المرحلة الدراسية
```

لا يضيف هذا القرار مستوى مادة جديدًا إلى المسار، ولا يغير ترتيب المستويات المعتمد:

```text
Course → Term → Chapter → Lesson
```

ولا يمنع الواجهة الحالية من عرض اسم المرحلة وحده عندما يكون سياق المادة ظاهرًا بوضوح. يظل اسم العرض منفصلًا عن المعرّف التقني.

### 3. معرّفات الـCourses الحالية

تُعتمد المطابقة التالية:

| المادة | اسم العرض للمرحلة | المعرّف التقني للـCourse |
|---|---|---|
| البرمجة والذكاء الاصطناعي | أولى بكالوريا | `programming-ai-baccalaureate-1` |
| البرمجة والذكاء الاصطناعي | ثانية بكالوريا | `programming-ai-baccalaureate-2` |

المعرّف التقني ثابت بعد نشر محتوى تحته، ولا يتغير إذا تغيّر اسم العرض أو الصياغة التسويقية للمادة أو المرحلة.

أي مادة أو نظام تعليمي جديد يحتاج جدول مطابقة معتمدًا قبل نشر أول URL تحته. لا يُخترع معرّف جديد أثناء رفع درس منفرد دون تسجيله في قرار أو سجل حاكم معتمد.

### 4. معرّفات الترمات

تُعتمد المطابقة التالية داخل كل Course:

| اسم العرض | المعرّف التقني |
|---|---|
| ترم أول | `term-1` |
| ترم ثاني | `term-2` |

لا يُستخدم التصفير في معرّف الترم، لأن الترمين الحاليين مجموعة صغيرة ومعروفة، ولأن المعرّف يعبّر عن هوية الترم لا عن ترتيب ملفات قابل للتمدد.

### 5. معرّفات الفصول

تأخذ الفصول معرّفات محلية داخل الترم بالنمط:

```text
chapter-<NN>
```

أمثلة:

```text
chapter-01
chapter-02
chapter-03
chapter-10
```

يُستخدم تصفير من خانتين للأرقام من 1 إلى 9 لتسهيل القراءة والسرد اليدوي المتكرر.

إذا تجاوز عدد الفصول 99، يستمر الرقم طبيعيًا:

```text
chapter-100
```

ولا يعاد ترقيم أي فصل منشور لتوحيد عدد الخانات.

### 6. معرّفات الدروس

تأخذ الدروس معرّفات محلية داخل الفصل بالنمط:

```text
lesson-<NN>
```

أمثلة:

```text
lesson-01
lesson-02
lesson-10
```

لا يتكرر رقم الفصل داخل معرّف الدرس. لذلك لا تُستخدم أسماء مثل:

```text
lesson-01-01
lesson-1-1
chapter-01-lesson-01
```

وجود الفصل في المستوى الأب يجعل تكراره داخل معرّف الدرس زائدًا ويزيد احتمال الخطأ اليدوي.

إذا تجاوز عدد الدروس داخل فصل واحد 99، يستمر الرقم طبيعيًا:

```text
lesson-100
```

ولا يعاد ترقيم أي درس منشور.

### 7. المسار الدائم الكامل

يكون النمط الدائم للدرس:

```text
https://parmaga.com/courses/<course>/<term>/<chapter>/<lesson>/
```

ويكون المسار المعتمد للدرس الأول من الفصل الأول في الترم الأول للصف الثاني في مادة البرمجة والذكاء الاصطناعي:

```text
https://parmaga.com/courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/
```

يقابل هذا الرابط ملف فعلي في المستودع:

```text
courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/index.html
```

تُستخدم الشرطة النهائية `/` في جميع الـcanonical URLs الخاصة بالمجلدات المنشورة.

لا يدخل `index.html` في الرابط الدائم أو في الروابط الداخلية أو في `canonical` أو `sitemap.xml`.

### 8. صفحات الفهرسة الهرمية

عند بدء نشر المحتوى، يكون لكل مستوى منشور ملف `index.html` حقيقي:

```text
courses/index.html
courses/<course>/index.html
courses/<course>/<term>/index.html
courses/<course>/<term>/<chapter>/index.html
courses/<course>/<term>/<chapter>/<lesson>/index.html
```

بعد نشر أول Course، لا يبقى `/courses/` مسارًا غير موجود. يصبح فهرسًا حقيقيًا يعرض الـCourses المنشورة ويربط إليها.

لا يُنشأ مجلد فارغ أو صفحة وهمية لمستوى غير منشور. المسارات غير المنشورة تبقى HTTP 404 حقيقيًا وفق `ADR-0001`.

### 9. فصل المعرّف عن العنوان والترتيب

جميع معرّفات `Course` و`Term` و`Chapter` و`Lesson` هويات تقنية دائمة، وليست عناوين عرض.

يجوز تغيير:

- عنوان الفصل.
- عنوان الدرس.
- الصياغة العربية أو الإنجليزية.
- الوصف.
- ترتيب العرض في فهرس الفصل.
- أرقام العرض البصرية إذا احتاج المنهج ذلك.

ولا يؤدي أي من هذه التغييرات إلى تغيير المعرّف التقني أو اسم المجلد أو URL المنشور.

بعد أول نشر، يصبح الرقم داخل `chapter-<NN>` أو `lesson-<NN>` معرّفًا دائمًا. لا يضمن بقاء العنصر في الموضع البصري نفسه إلى الأبد.

### 10. إعادة ترتيب المحتوى

يجوز تغيير ترتيب روابط الدروس داخل فهرس الفصل دون تغيير URLs.

إذا أصبح `lesson-03` معروضًا قبل `lesson-02`، يبقى كل منهما على مساره الأصلي. لا يعاد ترقيم المجلدات لتطابق ترتيب العرض الجديد.

ينطبق الحكم نفسه على الفصول داخل الترم.

لا تعتمد الواجهة أو أي عملية مستقبلية على الترتيب المعجمي لأسماء المجلدات بوصفه مصدر الحقيقة للترتيب التعليمي.

### 11. إعادة تسمية المحتوى

تغيير العنوان المرئي لا يغير المعرّف.

على سبيل المثال، يمكن تغيير عنوان درس من:

```text
مقدمة في الشبكات العصبية
```

إلى:

```text
كيف تتعلم الشبكات العصبية؟
```

مع بقاء مساره:

```text
lesson-01/
```

لا تحتوي معرّفات الفصول والدروس على كلمات مشتقة من عناوينها؛ وذلك لمنع كسر الروابط عند تحرير العناوين أو تصحيحها.

### 12. نقل درس منشور

لا يُنقل درس منشور إلى مسار جديد لمجرد إعادة ترتيب المنهج.

إذا احتاج فهرس فصل آخر إلى الإشارة إليه، يجوز الربط إلى URL الأصلي بدل نقل المستند.

إذا تغيرت هوية الدرس أو بنية المنهج بصورة تجعل النقل الحقيقي ضروريًا، يعامل ذلك بوصفه Migration مستقلة، ولا ينفذ ضمن تحديث محتوى عادي.

يجب أن تحافظ الـMigration على قابلية الوصول من الرابط القديم بإحدى الوسائل التي تسمح بها الاستضافة وقتها، مرتبة حسب الأفضلية:

1. Redirect دائم بحالة HTTP مناسبة إذا أصبحت البنية المستضيفة تدعمه.
2. قاعدة Redirect معتمدة في Cloudflare بقرار وتنفيذ مستقلين.
3. صفحة توافق ثابتة على المسار القديم تحتوي رسالة واضحة ورابطًا مباشرًا إلى الموقع الجديد، إذا لم يتوفر Redirect حقيقي.

لا تُستخدم JavaScript redirects أو SPA fallback.

لا يُعاد استخدام المسار القديم لمحتوى مختلف.

صفحة التوافق ليست بديلًا مكافئًا لـHTTP redirect؛ هي حل أخير يحافظ على إمكانية وصول الطالب عندما لا تدعم الاستضافة الحالية إعادة التوجيه على مستوى HTTP.

### 13. السنة الدراسية

لا تدخل السنة الدراسية في المسار الدائم الافتراضي.

لا يُستخدم نمط مثل:

```text
/courses/2026-2027/...
```

ولا:

```text
/courses/programming-ai-baccalaureate-2-2026-2027/...
```

التصحيحات وتحسينات الشرح وتحديث الأمثلة التي لا تغير هوية الدرس تُنشر في المسار نفسه.

إذا تغير المنهج جذريًا بحيث لم يعد المحتوى الجديد يمثل تقديم الـCourse نفسه، تُنشأ نسخة Course جديدة بمعرّف جديد بعد قرار معماري مستقل يحدد:

- سبب النسخة الجديدة.
- المعرّف الجديد.
- حالة النسخة السابقة.
- روابط الانتقال.
- قواعد الأرشفة والفهرسة.

لا يُضاف لاحقًا suffix مثل `v2` أو سنة أو رقم إصدار بصورة اعتباطية أثناء نشر درس منفرد.

تبقى URLs النسخة القديمة محفوظة، ولا تُنقل تلقائيًا إلى النسخة الجديدة إذا كان محتواها ما زال مختلفًا ومفيدًا.

### 14. مراسي الصفحات

يبقى نمط مراسي الصفحات المعتمد في `ADR-0003`:

```text
#page-<n>
```

أمثلة:

```text
#page-1
#page-2
#page-27
#page-100
```

لا يُستخدم التصفير داخل fragment:

```text
#page-01
```

غير معتمد.

رقم الصفحة يطابق ترتيب الصفحة المنشور داخل الدرس وقت اعتمادها أول مرة.

لا يعاد ترقيم صفحة منشورة بطريقة تكسر رابطها. وإذا احتاج ترتيب العرض إلى تعديل، تبقى المرساة القديمة مرتبطة بالصفحة نفسها ما لم تعتمد Migration صريحة.

### 15. مراسي المفاهيم

يُعتمد نمط مراسي المفاهيم:

```text
#concept-<slug>
```

يكون `<slug>`:

- إنجليزيًا دلاليًا.
- lowercase.
- مكتوبًا بـASCII.
- مفصول الكلمات بشرطات.
- ثابتًا بعد النشر.
- غير مشتق تلقائيًا من عنوان العرض.
- غير معاد الاستخدام لمعنى مختلف.

مثال:

```text
#concept-neural-network
#concept-convolutional-neural-network
#concept-training-data
```

توجد مرساة المفهوم في طبقة HTML الدلالية للدرس، لا داخل ملف SVG.

يحدد كاتب طبقة النص HTML اسم المرساة أثناء إعداد الدرس، ويُراجع الاسم قبل أول نشر. يصبح وجود المرساة داخل HTML المنشور هو مصدر الحقيقة، ولا يلزم إنشاء Manifest أو Registry منفصل في هذه المرحلة.

لا تُنشأ مرساة لكل جملة أو عنصر بصري. تُنشأ فقط للمفاهيم التي لها قيمة تعليمية فعلية كرابط مباشر.

إذا تغير اسم العرض لمفهوم منشور، تبقى المرساة كما هي.

إذا دُمج مفهوم مع قسم آخر، تبقى المرساة القديمة في أقرب موضع دلالي يشرح المفهوم، ولا تُمنح لمفهوم مختلف.

### 16. Canonical URLs

يحتوي كل مستند محتوى قابل للفهرسة على `rel="canonical"` مطلق يشير إلى URL المعتمد لذلك المستند.

Canonical الدرس النموذجي:

```text
https://parmaga.com/courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/
```

القواعد:

- يستخدم النطاق الأساسي `https://parmaga.com`.
- يحتوي الشرطة النهائية للمجلد.
- لا يحتوي `index.html`.
- لا يحتوي Query Parameters.
- لا يحتوي `#page-*`.
- لا يحتوي `#concept-*`.
- تشير صفحات الفهارس القابلة للفهرسة إلى نفسها.
- تشير صفحة الدرس الأصلية إلى نفسها.

صفحات التوافق غير القابلة للفهرسة الناتجة عن Migration ليست صفحات محتوى أصلية، ويحدد قرار الـMigration نفسه هل تستخدم Redirect حقيقيًا أو `noindex` أو canonical إلى الهدف وفق الإمكانات المتاحة وقتها. لا تجمع إشارات فهرسة متعارضة بصورة تلقائية.

### 17. `sitemap.xml`

يُنشأ `sitemap.xml` يدويًا في جذر المستودع عند تنفيذ أول محتوى تعليمي قابل للفهرسة.

لا ينشئه `ADR-0004` نفسه.

يحدّث ناشر المحتوى `sitemap.xml` في commit نشر المحتوى نفسه. لا يُنشر درس جديد ثم يؤجل إدخاله إلى Sitemap في commit غير محدد.

يسرد `sitemap.xml`:

- صفحة `/courses/` بعد نشرها.
- فهارس الـCourses المنشورة.
- فهارس الترمات المنشورة.
- فهارس الفصول المنشورة.
- صفحات الدروس المنشورة القابلة للفهرسة.
- أي صفحات أصلية أخرى تقرر فهرستها صراحة.

ولا يسرد:

- Fragments.
- ملفات SVG بوصفها صفحات مستقلة.
- URLs تحتوي `index.html`.
- Query-based URLs.
- مسارات 404.
- صفحات توافق قديمة غير قابلة للفهرسة.
- مسارات لمحتوى لم يُنشر بعد.

تتطابق كل قيمة `<loc>` مع canonical الصفحة حرفيًا.

يجوز حذف `<lastmod>` بدل كتابة تاريخ غير دقيق. وإذا استُخدم، يجب أن يمثل تعديلًا جوهريًا حقيقيًا للمحتوى لا مجرد إعادة نشر أو تغيير شكلي.

لا يعتمد القرار على ترتيب URLs داخل Sitemap.

يبقى `robots.txt` مُدارًا خارج المستودع بواسطة Cloudflare. لا ينشئ هذا القرار ملف `robots.txt` ولا ينقله إلى المستودع.

### 18. تسمية أصول SVG

توجد أصول صفحات الدروس تحت:

```text
assets/lessons/
```

تعكس شجرة الأصول مستويات مسار الدرس نفسها بعد حذف البادئة `courses/`.

للمسار:

```text
/courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/
```

تكون شجرة الأصول:

```text
assets/lessons/
└── programming-ai-baccalaureate-2/
    └── term-1/
        └── chapter-01/
            └── lesson-01/
                ├── page-001.svg
                ├── page-002.svg
                └── page-003.svg
```

تكون قاعدة الاشتقاق:

```text
/courses/<course>/<term>/<chapter>/<lesson>/
```

إلى:

```text
/assets/lessons/<course>/<term>/<chapter>/<lesson>/page-<NNN>.svg
```

تستخدم أسماء ملفات الصفحات تصفيرًا إلى ثلاث خانات:

```text
page-001.svg
page-002.svg
page-027.svg
page-100.svg
```

إذا تجاوز عدد الصفحات 999، يستمر الرقم طبيعيًا دون إعادة تسمية الملفات السابقة:

```text
page-1000.svg
```

تكون المطابقة بين المرساة واسم الأصل حتمية:

| المرساة | ملف الأصل |
|---|---|
| `#page-1` | `page-001.svg` |
| `#page-2` | `page-002.svg` |
| `#page-27` | `page-027.svg` |
| `#page-100` | `page-100.svg` |

لا تستخدم أسماء اعتباطية مثل:

```text
final.svg
new-page.svg
image-copy.svg
lesson-page-final-2.svg
```

لا تتطلب قاعدة التسمية تعديل المحتوى الداخلي لأي ملف SVG، ولا نقل نصوصه إلى HTML، ولا توحيد معرّفات `defs`، ولا إعادة توليده.

### 19. فصل أصول الدرس عن طبقة HTML

يبقى `index.html` الخاص بالدرس مسؤولًا عن:

- عنوان الدرس.
- البنية الدلالية.
- النص القابل للفهرسة والبحث.

- التنقل داخل الدرس.
- روابط السابق والتالي عند وجودها.

وتبقى ملفات SVG أصولًا مستقلة تُعرض عبر `<img>` وفق `ADR-0003`.

لا تُضمّن ملفات SVG inline افتراضيًا.

لا تحمل أسماء الملفات العناوين العربية أو نصوص المفاهيم. تستمد هويتها من مسار الدرس ورقم الصفحة فقط لتقليل العمل اليدوي ومنع Drift بين العنوان واسم الأصل.

### 20. دوام المعرّفات

بعد نشر أي معرف تقني أو مرساة للعامة:

- لا يُعاد استخدامه لمحتوى مختلف.
- لا يُغيّر بسبب تحسين لغوي.
- لا يُغيّر بسبب تعديل ترتيب العرض.
- لا يُغيّر لمجرد توحيد التصفير.

- لا يُحذف ثم يعاد منحه لعنصر آخر.

يجب أن يعامل أي تغيير ضروري في URL أو fragment منشور بوصفه Migration مستقلة، مع حصر الروابط المتأثرة وخطة توافق واختبارات للمسارات القديمة والجديدة.

### 21. حالة الدرس المحذوف أو المؤرشف

لا يُعاد استخدام URL درس منشور بعد حذفه من ترتيب المنهج.

إذا ظل المحتوى مفيدًا أو كانت له روابط واردة، يجوز إبقاء صفحة أرشيفية على المسار نفسه توضح حالته وتربط إلى البديل إن وجد.

إذا كان النشر نفسه قد أُلغي ولم يعد وجود الصفحة صحيحًا، يجوز أن يعيد المسار HTTP 404، لكن لا يُمنح لاحقًا لمحتوى مختلف.

تحديد استخدام HTTP 404 أو صفحة أرشيفية أو Migration يعتمد على سبب الإزالة، ويجب تسجيله عند تنفيذ الإزالة.

### 23. حدود ملفات SVG المعروفة

بقاء العرض عبر `<img>` يعني أن كل ملف SVG يعمل في نطاق مستند منفصل. لذلك لا يسبب تكرار أو اختلاف معرّفات `defs` بين ملفات SVG تعارضًا، ولا يفرض هذا القرار توحيدها.

CSS Custom Properties وDesign Tokens الموجودة في:

```text
assets/css/parmaga.css
```

لا تصل إلى المحتوى الداخلي لملف SVG المعروض عبر `<img>`. لذلك:

- ألوان SVG الحالية خارج نطاق Design Tokens.
- الوضع الليلي لا يعيد تلوين محتوى SVG تلقائيًا.
- القيم اللونية الموجودة داخل SVG لا تخالف قاعدة `:root` الخاصة بـCSS الموقع، لأنها ليست CSS صفحة المحتوى.
- تغيير هذا الحد مستقبلًا يحتاج قرارًا مستقلًا ولا يبرر تعديل ملفات SVG الحالية.

قد تستدعي ملفات SVG الحالية خطوط Windows مثل:

- `Tahoma`.
- `Segoe Print`.
- `Comic Sans MS`.

قد لا تتوفر هذه الخطوط على أندرويد، ومع تقطيع النص يدويًا بعناصر `tspan` وإحداثيات ثابتة قد يخرج النص عن الإطار عند استخدام خط بديل.

لا يعالج هذا القرار الملفات المولدة الحالية، ولا يفرض تعديلها. يكون العلاج في قالب التوليد القادم، ويكون اختبار عينة فعلية على هاتف أندرويد حقيقي شرطًا قبل اعتماد ذلك القالب للإنتاج واسع النطاق.

### 24. محاكاة الكتابة المؤجلة

لا يدخل تصور محاكاة الكتابة داخل SVG في نطاق هذا القرار.

يحافظ نظام المسارات وأسماء الأصول على إمكان إضافة سلوك عرض أو محاكاة مستقبلية دون تغيير URL الدرس أو اسم أصل SVG الأصلي.

أي اعتماد مستقبلي للمحاكاة يحتاج قرارًا مستقلًا لأنه قد يمس:

لا تُعدل ملفات SVG الحالية داخليًا لتهيئتها لمحاكاة مستقبلية غير معتمدة.

### 25. الأمان

- `foreignObject`.
- مراجع شبكية خارجية.

لا يضيف نظام التسمية ثقة تلقائية في الملف؛ الاسم الصحيح لا يغني عن فحص الأصل.

لا يغير هذا القرار نتيجة الفحص المسجلة للعينات الحالية، ولا يفرض تعديل محتواها.

## Alternatives Considered

### 1. Slugs عربية

مثال:

```text
/courses/ثانية-بكالوريا/ترم-أول/الفصل-01/الدرس-01/
```

رُفضت لأنها قد تظهر percent-encoded عند النسخ أو المعالجة، وتزيد كلفة التشغيل اليدوي، وتحمل محارف تحتاج ترميزًا في الروابط، بما يخالف قاعدة المعرّفات المعتمدة في `ADR-0003`.

إمكان فهرستها لا يزيل مخاطر المشاركة والنسخ والتعامل اليدوي مع الملفات.

### 2. نقل صوتي لاتيني للأسماء العربية

مثال:

```text
/courses/tanya-bakalorya/term-awal/chapter-01/lesson-01/
```

رُفض لعدم وجود معيار تهجئة واحد ثابت، ولأن اختلافات مثل `tanya` و`tania` أو `bakalorya` و`bacaloria` قد تنتج Drift ورغبة لاحقة في تصحيح URLs منشورة.

### 3. معرّفات رقمية خالصة

مثال:

```text
/courses/c02/t01/c01/l01/
```

رُفضت لأنها غير وصفية، وتحتاج جدولًا مرجعيًا مستمرًا لفهمها، وتزيد احتمال الخطأ عند رفع عدد كبير من الملفات يدويًا.

### 4. المرحلة وحدها داخل Course

مثال:

```text
/courses/baccalaureate-2/term-1/chapter-01/lesson-01/
```

كان هذا البديل أكثر تطابقًا مع الوصف الحالي لـ`Course` في `ADR-0003`، لكنه رُفض لأن إدخال مادة ثانية داخل المرحلة نفسها سيؤدي إلى تصادم أو إلى الحاجة لتغيير بنية جميع الروابط المنشورة.

### 5. مستوى مستقل للمادة

مثال:

```text
/courses/programming-ai/baccalaureate-2/term-1/chapter-01/lesson-01/
```

رُفض في المرحلة الحالية لأنه يضيف مستوى نشر جديدًا إلى التسلسل المعتمد، ويحتاج فهارس ومجلدات يدوية إضافية، ويعيد فتح نطاق أكبر من `ADR-0003`.

### 6. إدخال السنة الدراسية

مثال:

```text
/courses/2026-2027/programming-ai-baccalaureate-2/...
```

رُفض لأنه يجعل URLs موسمية، ويكرر المحتوى والمسارات حتى عند وجود تغييرات طفيفة، ويضيف مستوى غير معتمد إلى الشجرة.

### 7. Slugs مشتقة من عناوين الدروس

مثال:

```text
/lesson-how-neural-networks-learn/
```

رُفض لأن العناوين قابلة للتحرير والتصحيح، بينما URLs يجب أن تبقى ثابتة. كما يزيد هذا النمط زمن التسمية والمراجعة لكل درس.

## Consequences

### Positive

- تصبح جميع الروابط ASCII وقابلة للنسخ والمشاركة دون تضخم ناتج عن percent-encoding للأحرف العربية.
- يستطيع الإنسان فهم Course وTerm وChapter وLesson من المسار دون الرجوع إلى معرّفات رقمية غامضة.
- يمكن إضافة مادة أخرى مستقبلًا دون تغيير مسارات مادة البرمجة والذكاء الاصطناعي.
- لا يُضاف مستوى جديد إلى الشجرة المعتمدة في `ADR-0003`.
- يمكن اشتقاق مكان كل أصل SVG آليًا أو يدويًا من URL الدرس.
- يقل احتمال تسمية الملفات بأسماء اعتباطية أو وضعها تحت درس خاطئ.
- يمكن تعديل العناوين وترتيب العرض دون كسر URLs.
- تبقى روابط الصفحات والمفاهيم مستقرة داخل مستند الدرس.
- لا يتطلب القرار JavaScript أو Dependencies أو Router أو Build Step.
- لا يتطلب تعديل المحتوى الداخلي لملفات SVG.

### Negative

- معرّف Course أطول من معرّف يمثل المرحلة وحدها.
- يصبح تعريف Course أوسع من الوصف الأصلي في `ADR-0003`.
- لا تعكس أرقام الفصول والدروس بالضرورة ترتيب العرض المستقبلي بعد إعادة التنظيم.
- تحتاج كل عملية نشر إلى تحديث يدوي للفهارس والروابط وcanonical و`sitemap.xml`.
- لا توجد وسيلة داخل GitHub Pages الحالية لإنشاء HTTP redirects عامة من ملفات المستودع وحدها.
- نقل درس منشور بين الفصول يظل مكلفًا لأن الفصل جزء من URL.
- تراكم صفحات التوافق المحتملة يمثل كلفة صيانة إذا لم تُحترم قاعدة عدم تغيير المسارات.
- تحتاج مراسي المفاهيم إلى اختيار ومراجعة بشرية.
- لا تصل Design Tokens أو الوضع الليلي إلى داخل SVG المعروض عبر `<img>`.
- تظل طبقة النص HTML عملًا يدويًا مطلوبًا لكل درس وصفحة.
- لا يحل القرار خطر اختلاف الخطوط داخل SVG على أندرويد.

## Implementation Boundary

هذا القرار يوثق النظام فقط.

لا ينشئ في مرحلته التوثيقية:

- `courses/`.
- `assets/lessons/`.
- `sitemap.xml`.
- درسًا تجريبيًا.
- ملف SVG.
- CSS.
- JavaScript.
- صفحة فهرس.
- Redirect.
- أي تعديل في الملفات الحاكمة الأخرى.

```text
/courses/programming-ai-baccalaureate-2/term-1/chapter-01/lesson-01/
```

## Verification Requirements for Future Content

عند تنفيذ أول نموذج مرجعي، يجب التحقق على الأقل من:

- أن كل مجلد منشور يحتوي `index.html` بهذه الحالة الحرفية.
- أن كل URL canonical ينتهي بشرطة `/`.
- أن URLs التي تحتوي `index.html` ليست هي الروابط المعتمدة.
- أن `/courses/` يعيد HTTP 200 بعد نشر فهرسه.
- أن المسارات المنشورة المطلوبة تعيد HTTP 200.
- أن مسارًا مشابهًا بحالة أحرف خاطئة لا يصبح alias معتمدًا.
- أن المسارات غير الموجودة تعيد HTTP 404 حقيقيًا.
- أن كل `<loc>` في `sitemap.xml` يطابق canonical صفحة منشورة.
- أن fragments من نمط `#page-*` و`#concept-*` تشير إلى IDs موجودة.
- أن كل ملف صفحة يتبع `page-<NNN>.svg`.
- أن كل أصل SVG محمّل ينتمي إلى الدرس الحالي فقط.
- أن الصفحة لا تحمّل أصول درس آخر.
- أن SVG يُعرض عبر `<img>` ولا يُضمّن inline دون قرار مستقل.
- أن ملفات SVG الأصلية لم تُعدّل داخليًا.
- أن عينة SVG تُفحص على هاتف أندرويد حقيقي قبل اعتماد قالب التوليد القادم.

## Rollback

يمكن التراجع عن مرحلة توثيق هذا القرار وحدها بحذف ملف `ADR-0004` في commit عكسي قبل نشر أي محتوى يعتمد عليه.

بعد نشر أول URL أو أصل وفق هذا النظام، لا يعود التراجع عن المعرّفات تغييرًا توثيقيًا بسيطًا. يصبح Migration عامة تحتاج الحفاظ على الروابط القديمة ومعالجة canonical و`sitemap.xml` والفهارس والروابط الواردة.

قبل دفع commit توثيق هذا القرار، يمكن التراجع عنه دون استخدام `reset --hard` أو `clean` أو `--force`.

بعد دفعه، يكون الرجوع باستخدام `git revert`.

بعد نشر محتوى فعلي، لا يجوز حذف هذا القرار أو تغييره بطريقة توحي بأن المسارات المنشورة لم تعد ملزمة؛ يجب إصدار ADR أحدث يصف Migration صراحة.
