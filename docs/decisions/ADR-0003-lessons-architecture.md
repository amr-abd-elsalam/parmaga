# ADR-0003: معمارية نشر الدروس والروابط الدائمة

## Status

Accepted

## Context

موقع Parmaga حاليًا موقع HTML وCSS ثابت، مستضاف على GitHub Pages مع Cloudflare أمامه. لا يوجد JavaScript خاص بالمشروع، ولا Dependencies، ولا Build Step، ولا Router، ولا SPA fallback. المسارات غير الموجودة تعيد HTTP 404 حقيقيًا، وتُقدَّم عبر `404.html`.

يحتوي المشروع حاليًا على صفحة هبوط واحدة وصفحة خطأ واحدة، وهوية Parmaga Memo مطبقة على كلتيهما، مع Page Scopes هما `page-home` و`page-not-found` فقط. كل الأنماط تأتي من ملف CSS خارجي واحد في `assets/css/parmaga.css`، مقسم إلى طبقات Tokens وBase / Reset وComponents وPage Scopes، ثم طبقة Print.

لا توجد حتى الآن دروس، ولا محتوى تعليمي، ولا ملفات SVG، ولا Lesson Viewer، ولا اختبارات، ولا CI.

تبدأ الدراسة الفعلية في 1 سبتمبر 2026، وتُنشر الدروس تدريجيًا بعد كل Session أوفلاين. أي أن المشروع سيدخل مرحلة نشر متكرر ومتزايد على مدى شهور، لا مرحلة نشر مكتمل مرة واحدة. هذا يجعل قرار بنية المسارات والروابط الدائمة قرارًا يجب حسمه قبل نشر أول درس، لأن تغييره بعد النشر يكسر روابط الطلبة ويكسر الفهرسة.

سجّل `ADR-0001` أن الاستضافة تبقى مؤقتًا على GitHub Pages مع Cloudflare، وأن المسارات غير الموجودة تبقى بحالة HTTP 404 دون Router ودون SPA fallback، ثم سجّل في نتائجه أن النمط المرشح مستقبلًا هو مجلد لكل درس يحتوي `index.html`، ووصف ذلك صراحة بأنه اتجاه مستقبلي مسجل فقط وغير منفذ، وترك للمعماري القادم حرية إعادة تقييمه.

سجّل `ADR-0002` ملف CSS خارجيًا واحدًا مبنيًا على Design Tokens، وجعل كتلة `:root` المكان الوحيد المسموح فيه بقيم الألوان الخام، واعتمد Parmaga Memo Palette مصدر الحقيقة للألوان، ثم سجّل صراحة أن شكل الدروس قرار مفتوح مؤجل خارج نطاقه، يجب حسمه قبل 1 سبتمبر 2026.

هذا الـADR يسدّ الفراغ الذي سجّله `ADR-0002` بنفسه، ويحوّل الاتجاه المرشح في `ADR-0001` إلى قرار معماري معتمد، دون تعديل أي منهما.

قدّم مالك المشروع توضيحًا معتمدًا لبنية المحتوى الحالية: الطلبة مقسمون إلى مرحلتين، ولكل مرحلة ترمان، ويحتوي كل ترم عددًا متغيرًا من الفصول، ويحتوي كل فصل عددًا متغيرًا من الدروس.

كما تطلب رؤية المشروع أن يستطيع الطالب الرجوع إلى صفحة أو مفهوم محدد داخل الدرس عبر رابط مباشر، وأن يعمل ذلك على الهاتف والكمبيوتر وفي ظروف إنترنت مختلفة. أي أن الروابط المباشرة متطلب منتج، لا تحسينًا اختياريًا.

المخاطر المعروفة عند غياب هذا القرار هي: تغيّر مسارات الدروس بعد النشر، وتكرار CSS داخل صفحات المحتوى، وتباعد الهوية بين الصفحات مع تزايد العدد، وظهور روابط داخلية غير متسقة، والانجرار إلى Router أو Build Step قبل وجود حاجة فعلية تبرره.

هذا الـADR قرار توثيقي فقط. لا ينفذ أي درس، ولا ينشئ أي مجلد، ولا يعدل أي ملف قائم.

## Decision

### 1. نموذج المحتوى

- التسلسل المعتمد هو `Course → Term → Chapter → Lesson`.
- `Course` هو أعلى مستوى نشر في هذه المرحلة، ولا يُضاف أي مستوى فوقه الآن.
- `Course` يمثل في الحالة الحالية المرحلة الدراسية، أي المسار التعليمي الأعلى، لا المادة الواحدة.
- أسماء العرض العربية الحالية المعتمدة لـ`Course` هي: `أولى بكالوريا` و`ثانية بكالوريا`.
- لكل `Course` ترمان، وأسماء العرض العربية المعتمدة لهما هي: `ترم أول` و`ترم ثاني`.
- `Chapter` يتبع `Term`، و`Lesson` يتبع `Chapter`.
- عدد `Chapters` داخل كل `Term` متغير، وليس قيمة ثابتة في المعمارية.
- عدد `Lessons` داخل كل `Chapter` متغير، وليس قيمة ثابتة في المعمارية.
- لا تعتمد المعمارية على أي عدد ثابت في أي مستوى، ولا تفترض تساوي الفروع.
- لا يعرّف هذا القرار أسماء `Chapters` أو `Lessons`، ولا أعدادها، ولا `Course` ثالثًا، ولا ترمًا إضافيًا.
- تمثيل `Course` بوصفه المرحلة الدراسية وصف للحالة الحالية، ويجوز لقرار معماري مستقل لاحق إعادة تقييمه إذا تعددت المواد داخل المرحلة.

### 2. الشجرة الثابتة

- تُنشر الدروس على الأساس الثابت الحالي، دون Router ودون JavaScript ودون Dependencies ودون Build Step.
- يُخصص فهرس أعلى للـCourses، ثم مجلد لكل `Course`، ثم مجلد لكل `Term` داخله، ثم مجلد لكل `Chapter`، ثم مجلد لكل `Lesson`.
- يحتوي كل مستوى منشور على ملف `index.html` فعلي، فيكون كل مستوى مستندًا حقيقيًا يعيد HTTP 200.
- النمط العام المعتمد، بصيغة وصفية غير تنفيذية:

```text
courses/
    index.html
    <course>/
        index.html
        <term>/
            index.html
            <chapter>/
                index.html
                <lesson>/
                    index.html
```

- الرموز بين قوسين زاويين في هذا القرار تمثل مواضع معرّفات تقنية لم تُعتمد بعد. هي notation وصفي لشكل الشجرة، وليست slugs مقترحة ولا أسماء مجلدات نهائية.
- لا يُنشأ أي من هذه المجلدات في مرحلة هذا القرار.

### 3. Canonical URLs

- يعكس الرابط الدائم للدرس التسلسل `Course / Term / Chapter / Lesson` بترتيبه.
- تُستخدم مسارات مجلدات نظيفة، مع شرطة نهائية في الـcanonical URL، ويقابلها `index.html` فعلي داخل المجلد.
- شكل الرابط الدائم للدرس، بصيغة وصفية:

```text
https://parmaga.com/courses/<course>/<term>/<chapter>/<lesson>/
```

- تكون الروابط الداخلية متسقة مع الـcanonical URL نفسه، فلا يوجد أكثر من شكل للوصول إلى المستند نفسه.
- لا يُستخدم Query-based routing، ولا تُحمل حالة التنقل في Query String.
- لا يُضاف Router، ولا SPA fallback، ولا Redirect لتوليد هذه المسارات.
- لا يعتمد هذا القرار أي slug فعلي للمراحل أو الترمات أو الفصول أو الدروس. اختيار المعرّفات الفعلية مؤجل.

### 4. الروابط المباشرة داخل الدرس

- الدرس هو المستند HTML الأساسي القابل للفهرسة، وهو أصغر وحدة لها URL مستقل.
- الصفحة داخل الدرس والمفهوم داخل الدرس يُشار إليهما بـfragment ID ثابت على مستند الدرس نفسه.
- شكل الروابط المباشرة، بصيغة وصفية:

```text
https://parmaga.com/courses/<course>/<term>/<chapter>/<lesson>/#page-<n>
https://parmaga.com/courses/<course>/<term>/<chapter>/<lesson>/#concept-<name>
```

- تُستخدم بادئة `page-` للصفحات وبادئة `concept-` للمفاهيم، لتمييز نوع المرساة ومنع التعارض بين الفضاءين.
- الـfragments ليست HTTP resources مستقلة، ولا تعيد استجابات منفصلة، ولا تُعامل كصفحات في الفهرسة.
- الـcanonical URL للدرس لا يحتوي fragment.
- أي ID منشور لا يُعاد استخدامه لمحتوى مختلف، لأن ذلك يحوّل الروابط المحفوظة عند الطلبة إلى روابط مضللة تعمل وتشير إلى الشيء الخطأ.
- هذا القرار يسجل الأنماط والقواعد فقط، ولا ينشئ أي ID فعلي ولا أي محتوى درس.
- تقسيم الدرس إلى صفحات هو تقسيم داخلي للمستند، ولا يُترجم في هذه المرحلة إلى مستوى نشر خامس تحت `Lesson`.

### 5. مكان الملفات والأصول

- ملف `index.html` الخاص بالدرس يحمل البنية الدلالية، والتنقل، والنص المتاح للفهرسة والبحث والقراءة.
- أصول SVG التعليمية، عند وجودها واعتمادها، تبقى ملفات مستقلة، ولا تُضمَّن inline افتراضيًا.
- تُستخدم مساحة مستقلة لأصول الدروس تحت `assets/lessons/` مستقبلًا، منفصلة عن أصول الهوية والصور الحالية.
- لا تُنشأ هذه المساحة في مرحلة هذا القرار.
- لا تُعدَّل ملفات SVG الأصلية صامتًا، ولا يُحقن فيها أي محتوى تنفيذي.
- تحتاج أي ملفات SVG قبل نشرها إلى فحص أمني ووصولي، يشمل التأكد من خلوها من Scripts أو مراجع خارجية غير مقصودة، ومن ملاءمة النص البديل أو الوصف المرافق.
- لا يُضاف أي executable content إلى المشروع بموجب هذا القرار.

### 6. Styling

- تعيد كل صفحات المحتوى المستقبلية استخدام ملف CSS المشترك الوحيد `assets/css/parmaga.css`.
- لا يُضاف CSS مضمّن داخل صفحات الدروس، ولا ملف CSS موازٍ خاص بالدروس.
- تبقى Memo Palette داخل `:root` مصدر الحقيقة للألوان، كما اعتمد `ADR-0002`.
- تُعاد استخدام هوية Parmaga Memo عبر الملف المشترك، لا بتكرار قواعدها في كل صفحة.
- عند تنفيذ أول درس حقيقي، يمكن إضافة body class وPage Scope صريح للدروس، ضمن مرحلة تنفيذ مستقلة ومعتمدة.
- لا يُعدَّل CSS في مرحلة هذا القرار.
- لا تُستخدم Tokens غير مستخدمة لمجرد وجودها، ولا يُضاف Token جديد بلا حاجة مثبتة.

### 7. الفهرسة والتنقل

- تعمل صفحات مستويات `Course` و`Term` و`Chapter` كفهارس HTML ثابتة تسرد ما تحتها.
- يتم التنقل إلى المستوى الأب، والتنقل بين الدروس عبر Previous و Next، بروابط HTML أصلية فقط.
- لا يحتاج أي من ذلك إلى JavaScript، ولا إلى توليد وقت التشغيل.
- كل درس جديد مستقبلًا يجب أن يُحدِّث فهرس الـ`Chapter` التابع له والروابط المتأثرة في commit واحد، حتى لا توجد لحظة يكون فيها الفهرس متأخرًا عن المحتوى المنشور.
- لا يعتمد هذا القرار Header عامًا ولا Nav مشتركًا ولا Sticky bar. أي عنصر تنقل عام يحتاج قرارًا أو مرحلة مستقلة.

### 8. العلاقة مع القرارات السابقة

- لا يوجد تعارض بين هذا القرار و`ADR-0001`.
- سجّل `ADR-0001` مجلدًا لكل درس يحتوي `index.html` بوصفه اتجاهًا مرشحًا غير منفذ، وترك إعادة تقييمه مفتوحة.
- يعتمد `ADR-0003` هذا المبدأ ويوسعه إلى مجلد يحتوي `index.html` لكل مستوى: `Course` و`Term` و`Chapter` و`Lesson`.
- يبقى `ADR-0001` كما هو: لا يُعدَّل، ولا يُعلن Superseded، ولا يُنفَّذ له Supersede.
- يبقى `ADR-0002` كما هو، ويُحترم قراره في ملف CSS الواحد وفي Memo Palette مصدرًا للألوان.
- هذا القرار يحسم الجزء المتعلق ببنية النشر والروابط الدائمة من الفراغ الذي سجّله `ADR-0002`، ولا يعدل نص `ADR-0002` ولا حالته.

### 9. سلوك 404

- يبقى `404.html` دون تعديل.
- تستمر المسارات غير الموجودة في إعادة HTTP 404 حقيقي.
- لا يُضاف Redirect، ولا SPA fallback، ولا Router، ولا أي معالجة تحوّل الخطأ إلى HTTP 200.
- لا تُضاف روابط دروس إلى صفحة 404 في هذه المرحلة.
- يبقى `noindex` في صفحة 404 كما هو.

### 10. SEO

- وحدة SEO الأساسية حاليًا هي الدرس، لا كل fragment داخله.
- تحتاج صفحات الفهارس وصفحات الدروس المستقبلية، عند تنفيذها، إلى عنوان ووصف وcanonical ذاتية وفريدة لكل مستند.
- لا تُنفَّذ أي metadata في مرحلة هذا القرار.
- لا يُضاف sitemap، ولا Structured Data، ولا Open Graph أو Twitter Cards جديدة.
- لا يُعدَّل `robots.txt`، وهو يبقى مُدارًا من Cloudflare خارج مصدر الحقيقة داخل الـRepository، كما سجّل `ADR-0001`.

### 11. الأداء

- ملف CSS مشترك واحد لكل الصفحات.
- صفر JavaScript خاص بالمشروع، وصفر Webfonts، وصفر Dependencies، وصفر Build Step.
- لا يُحمّل الدرس أصول دروس أخرى، فيبقى وزن الصفحة مرتبطًا بمحتواها فقط.
- عند تنفيذ أصول SVG مستقبلًا، تُسجَّل أهمية الأبعاد الصريحة لمنع Layout Shift، وأهمية اختيار سياسة تحميل مناسبة لعدد الأصول داخل الدرس.
- لا يُنفَّذ preload ولا lazy loading في مرحلة هذا القرار.
- الأثر المتوقع لهذا القرار على Production هو صفر، لأنه لا يضيف أي network request ولا يعدل أي HTML أو CSS أو Asset.

### 12. الوصولية

يجب أن يحافظ التنفيذ المستقبلي على الآتي، وهي متطلبات مسجلة لم تُنفَّذ بعد:

- HTML دلالي، وروابط أصلية بدل عناصر قابلة للنقر مصنوعة يدويًا.
- تسلسل عناوين صحيح ومتصل داخل كل مستند.
- الحفاظ على Focus indicator الحالي وعدم إلغائه.
- عدم الاعتماد على اللون وحده لنقل المعنى.
- نص بديل مناسب للأصول، وTranscript أو وصف HTML عندما لا يكفي النص البديل.
- عدم إضافة Motion.
- IDs فريدة وثابتة داخل كل مستند، لأن الروابط المباشرة تعتمد عليها.

### 13. التسمية ومنع Drift

- أسماء العرض العربية منفصلة تمامًا عن المعرّفات التقنية.
- أسماء العرض تُستخدم للطالب في النص المرئي، والمعرّفات التقنية تُستخدم في المسارات والـIDs.
- تكون المعرّفات التقنية ثابتة، وآمنة للمسارات، وقابلة للقراءة، ولا تحمل مسافات أو محارف تحتاج ترميزًا في الروابط.
- لا يخترع هذا القرار أي معرّف تقني فعلي؛ تُعتمد المعرّفات مع أول محتوى حقيقي.
- لا يُغيَّر URL درس بعد نشره إلا بقرار Migration مستقل يعالج الروابط القديمة صراحة.
- لا تُعاد ترقيم صفحات منشورة بطريقة تكسر الـfragments القائمة.
- كل درس جديد يُنشر مع ملفه، وأصوله، وتحديث فهرس الـ`Chapter`، وتحديث Previous و Next المتأثرة، في commit واحد.
- يبقى العمل اليدوي مقبولًا في الحجم الحالي، ولا يُضاف Build Step لتفادي مشكلة لم تظهر بعد.
- إذا ظهر Drift فعلي ومتكرر مع وصول المحتوى إلى عشرات الدروس، يُعاد تقييم Build Step بقرار معماري مستقل. اعتماده ليس مفترضًا مسبقًا بموجب هذا القرار.

### 14. وحدة النشر والتراجع

- مرحلة هذا القرار نفسها قابلة للتراجع بحذف ملف الـADR عبر `git revert` لـcommit واحد.
- كل درس مستقبلي يجب أن يكون وحدة commit مستقلة وكاملة.
- التراجع عن commit الدرس يحذف الدرس وأصوله، ويعيد فهرس المستوى الأب وروابط Previous و Next إلى حالتها السابقة.
- بعد التراجع يعود مسار الدرس إلى HTTP 404 حقيقي، وهو السلوك الصحيح المقصود لا خللًا.
- لا توجد قاعدة بيانات ولا حالة مخزنة ولا state migration مرتبطة بهذا القرار.

### 15. ما هو مؤجل

يُسجَّل صراحة أن الآتي مؤجل وغير محسوم بموجب هذا القرار:

- المعرّفات الفعلية للمراحل والترمات والفصول والدروس.
- أول محتوى تعليمي.
- Lesson Viewer متقدم.
- أي JavaScript.
- تتبع التقدم.
- البحث.
- الحسابات.
- العمل دون اتصال.
- Build Step.
- Dependencies.
- الاختبارات وCI.
- sitemap وStructured Data.
- أي Migration للاستضافة.
- أي إعادة تصميم للصفحة الرئيسية أو صفحة 404.

## Consequences

يصبح لدى المشروع مسار نشر واضح للدروس قبل بدء الدراسة، ويمكن نشر درس واحد في كل مرة دون انتظار اكتمال المنهج، ودون تغيير في بنية الموقع القائمة.

تصبح الروابط الدائمة محسومة قبل نشر أول درس، فينخفض خطر كسر روابط الطلبة والفهرسة لاحقًا، ويصبح تغيير أي URL منشور حدثًا يحتاج قرار Migration صريحًا لا تعديلًا عابرًا.

يبقى الموقع HTML وCSS ثابتًا: صفر JavaScript خاص بالمشروع، وصفر Dependencies، وصفر Build Step، وصفر Router. ويبقى ملف CSS الواحد مصدر الهوية، فتُعاد استخدام Memo identity دون تكرار قواعد بصرية في كل صفحة.

تبقى فهرسة المحتوى والتنقل بين الدروس ممكنة بروابط HTML أصلية فقط، وهو أخف على الشبكة وأكثر متانة في ظروف الإنترنت الضعيفة، ويعمل حتى لو تعطل أي مصدر خارجي.
